# Cortext Architecture Specification

## 1. Role & Identity
Cortext is a sovereign, local, headless cognitive working-memory daemon for Linux.
It intercepts `/v1/chat/completions` requests from local frontends (Aether OmniBar, CLI pipes, editors), resolves relevant entity subgraphs from an embedded SQLite graph, injects a deduplicated context delta into the prompt, and proxies the call to a chosen frontier LLM.

## 2. Storage Schema (`~/.config/cortext/memory.db`)
Using `aiosqlite` and `sqlite-vec`:

1. `entities`:
   - `id` INTEGER PRIMARY KEY AUTOINCREMENT
   - `name` TEXT UNIQUE NOT NULL
   - `archetype` TEXT NOT NULL (person, project, system, vehicle, concept; Personality Matrix: trait, directive, preference, see below)
   - `summary` TEXT DEFAULT ''
   - `metadata` JSON DEFAULT '{}'
   - `origin` TEXT NOT NULL DEFAULT 'user_explicit' ('user_explicit', 'model_inferred', 'system')
   - `confidence` REAL NOT NULL DEFAULT 1.0 (0.0-1.0; higher confidence wins on upsert, user_explicit is never displaced at equal confidence; resolver tags < 0.8 as `[inferred]`)
   - `created_at`, `updated_at` DATETIME
   - `access_count` INTEGER NOT NULL DEFAULT 0 (times recalled into a context delta; migrated onto older DBs)
   - `last_accessed_at` DATETIME (NULL until first recall; set by `touch_access`)

2. `edges`:
   - `id` INTEGER PRIMARY KEY AUTOINCREMENT
   - `source_id` INTEGER NOT NULL (FK -> entities.id)
   - `target_id` INTEGER NOT NULL (FK -> entities.id)
   - `relation` TEXT NOT NULL
   - `weight` REAL NOT NULL DEFAULT 1.0
   - `metadata` JSON DEFAULT '{}'
   - `origin` TEXT NOT NULL DEFAULT 'user_explicit' ('user_explicit', 'model_inferred', 'system')
   - `confidence` REAL NOT NULL DEFAULT 1.0 (0.0-1.0; higher confidence wins on upsert, user_explicit is never displaced at equal confidence; resolver tags < 0.8 as `[inferred]`)
   - `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP (migrated onto older DBs; bumped on deprecation and winning upserts)
   - `access_count` INTEGER NOT NULL DEFAULT 0 and `last_accessed_at` DATETIME (same semantics as on entities; migrated onto older DBs)
   - UNIQUE(source_id, target_id, relation)
   - Deprecation: a severed edge is never deleted; it keeps its row with `weight = 0.0`, `confidence = 0.0`, `metadata.deprecated = true` and `metadata.deprecation_reason`.

3. `episodes`:
   - `id` INTEGER PRIMARY KEY AUTOINCREMENT
   - `timestamp` REAL NOT NULL
   - `session_id` TEXT NOT NULL
   - `narrative` TEXT NOT NULL
   - `extracted_entities` JSON DEFAULT '[]'
   - `compacted_at` DATETIME (NULL until session compaction processes the episode; migrated onto older DBs)

4. `entity_embeddings`:
   - `entity_id` INTEGER PRIMARY KEY (vec0 virtual table, float[384]); written by `upsert_entity(embedding=...)`, queried by `find_similar_entities` (KNN, L2 distance) for the resolver's semantic tier, deleted with the entity.

### Personality Matrix archetypes
Three further `entities.archetype` values form an adaptive Personality Matrix. No table or column changes: they are ordinary rows in `entities` and `edges`, so confidence/origin precedence, deprecation, forgetting, privacy and SessionLedger deduplication apply unchanged.
- `trait`: internal character, emotional stance and demeanor (e.g. "Sovereign systems peer, dry wit, unhurried, calm").
- `directive`: inflexible behavioral rules and invariants (e.g. "Never apologize or use conversational filler").
- `preference`: stylistic output formats (e.g. "Provide code updates as unified git diffs", "Torque specs in Nm").
They are linked from the `User` entity by `prefers` (preference), `demands` (directive) or `enforces` (trait / standing rule) edges. A changed or contradicted rule is retired by deprecating its edge (`deprecated_edges`); a personality node with edges but none live is superseded and no longer recalled.

## 3. Module Directory (`src/cortext/`)
- `common.py`: dependency-free leaf module (imports nothing from `cortext`): shared constants (`EMBEDDING_DIM`, `MIN_EDGE_CONFIDENCE`, `MODEL_CONFIDENCE`, `MAX_SUMMARY_LEN`) and shared helpers (`extract_json`, `load_metadata` (malformed JSON yields `{}`), `aliases_of`, `clean_text`, `truncate`, `strip_think`: removes case-insensitive, multiline `<think>`, `<thinking>`, `<thought>` and `<reasoning>` blocks, each closed only by its own tag, an unclosed block running to the end of the text; `is_private(archetype, metadata)`: the single privacy predicate, see Section 4). It also owns the archetype sets `FACTUAL_ARCHETYPES`, `PERSONALITY_ARCHETYPES` (`trait`, `directive`, `preference`) and `VALID_ARCHETYPES` (their union, imported by `distill.py`).
- `schema.py`: sole home of DDL (`SCHEMA_SQL`, `VEC_SCHEMA_SQL`), schema setup and column migrations: `run_migrations(conn, vec_enabled)` is called by `DatabaseManager.connect`. When `vec_enabled`, it also runs `ORPHAN_VECTOR_SWEEP_SQL` (`DELETE FROM entity_embeddings WHERE entity_id NOT IN (SELECT id FROM entities)`), so vectors left behind by historical drops are removed on every connect.
- `host.py`: dependency-free leaf module (imports nothing from `cortext`). `get_host_context()` returns `user`, `hostname`, `os` (`platform.freedesktop_os_release()` PRETTY_NAME, falling back to `platform.platform()`), `desktop`/`session` (`XDG_CURRENT_DESKTOP`/`XDG_SESSION_TYPE`), `cpu` (`/proc/cpuinfo` model name) and `ram_gb` (`/proc/meminfo` MemTotal); unreadable `/proc` yields `''`/`0.0`. `format_host_context` renders it on one line.
- `onboarding.py`: COG-2 grounding. `seed_operator_anchor(db, host_info) -> (user_id, host_id)` upserts the operator `person` (capitalized user name, alias `User`) and the `system` host and links them `(User) --[operates_host]--> (Host)` (weight 1.0, confidence 1.0, `user_explicit`); an existing operator is returned without being overwritten, so it is idempotent. `onboarding_directive(host_info)` builds the `[Onboarding Directive: Grounding & Resonance]` block.
- `db.py`: `DatabaseManager` (aiosqlite). Focuses purely on connection lifecycle, PRAGMAs, query execution, transactions and graph traversal; DDL, schema setup and migrations live in `schema.py`. Opens the DB, loads `sqlite-vec`, applies `PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`, then delegates to `schema.run_migrations`. Exposes the public `transaction()` async context manager (serialized writer; commit/rollback). Enforces POSIX modes at runtime: parent dir `0700`, DB/`-wal`/`-shm` files `0600` (chmod errors from non-owners are ignored). Provides `touch_access(entity_ids, edge_ids)` (one transaction; `access_count += 1`, `last_accessed_at = CURRENT_TIMESTAMP`; duplicate ids count once, empty lists are a no-op), `deprecate_edge(source, target, relation, reason="deprecated")` (entity ids or names; canonical names and `metadata.aliases` resolve; relation casefolded; sets weight/confidence 0.0 and `metadata.deprecated`/`deprecation_reason`, bumps `updated_at`, keeps the row; returns False when no active matching edge exists; a later winning `upsert_edge` of the same triple revives it), `get_entity_subgraph(..., active_only=False)` (when true, deprecated edges are neither returned nor traversed; row metadata is parsed with `load_metadata`, so corrupt JSON yields `{}`), `upsert_entity` (an optional 384-float embedding replaces the row in `entity_embeddings`, only when the assertion wins on provenance), `upsert_edge` (confidence/origin precedence), `find_similar_entities(query_embedding, limit=5, distance_threshold=1.0)` (sqlite-vec KNN, L2 distance: `WHERE embedding MATCH ? AND k = ? ORDER BY distance`, keeps `distance <= threshold`, returns entity ids nearest first), `find_duplicate_entity(name, archetype, summary, distance_threshold=0.45)` (case-insensitive exact name/`metadata.aliases` match, then vector KNN restricted to the same archetype; string-only when vectors or the embedder are unavailable), `merge_entity_alias(id, alias, summary, origin, confidence)` (appends a de-duplicated alias, fills an empty summary, applies confidence by provenance precedence, always bumps `updated_at`), `upsert_entity_deduped` (find + merge, else plain `upsert_entity`), `get_entity_subgraph`, `record_episode`. Dropping an entity (`cli.py`) also deletes its `entity_embeddings` row. **Subgraph privacy (ROB-4):** the recursive CTE in `get_entity_subgraph` joins `entities` and refuses to walk into private entities (`archetype = 'private'` or `metadata.private` true) inside the walk itself, i.e. before the SQL `LIMIT`, so hidden nodes cannot consume hop or edge quota and crowd out visible facts.
- `embed.py`: `Embedder` protocol (`embed(text) -> list[float]`) and `EmbeddingManager`, a `fastembed.TextEmbedding` wrapper (default `BAAI/bge-small-en-v1.5`, 384 dims, matching `entity_embeddings`). `fastembed` is imported and the model built lazily on first `embed`, so imports, the CLI and tests never pay load cost. A `model_factory` or any custom `Embedder` can be injected for offline tests; wrong-dimension output raises `ValueError`.
- **Embedder wiring:** `daemon.build_app` builds one lazy `EmbeddingManager` and shares it with `ContextResolver(..., embedder=...)` (semantic tier) and `DatabaseManager(..., embedder=...)`, so daemon startup stays fast. When a `DatabaseManager` has an embedder and `upsert_entity` gets `embedding=None`, it embeds `f"{name}: {summary}"` (just `name` when the summary is empty; see `db.embedding_text`) off the event loop; an embedder failure is logged and never blocks the write. An explicit `embedding` always wins. `cortext embed-backfill` (`cli.py`) embeds every entity with no `entity_embeddings` row using the same text format and reports the count; re-running it is a no-op.
- `extractors.py`: Model B. `LLMExtractor(base_url, model_name, api_key="ollama")` is an async `Extractor` (`(query, response) -> extraction`) for `DistillationEngine`. It POSTs to a local OpenAI-compatible `{base_url}/chat/completions` (Ollama, vLLM) with a concise system prompt demanding strict JSON: `entities` (name, archetype, summary) , `edges` (source, target, relation) and `deprecated_edges` (source, target, relation, reason; emitted only when the user explicitly says a relationship ended, was replaced, sold, stopped or invalidated) plus optional `forgotten_entities` (list of names; emitted only when the user explicitly commands the system to forget, delete, scrub or erase an entity, and never also listed as an entity or edge endpoint). `parse_extraction` defaults `forgotten_entities` to `[]` when missing or malformed. `parse_extraction` tolerates code fences and surrounding prose, drops malformed items, and any transport error, non-2xx status or unparsable JSON yields empty lists, so the exchange is still recorded as an episode. Output flows through the normal ingestion defenses (sanitization, grounding, provenance: `model_inferred` at 0.6, edge requirement). `daemon.build_app` uses it only when `extractor_model` is set (URL defaults to `http://127.0.0.1:11434/v1`); otherwise `heuristic_extract` stays the default. Distillation is a background task, so SLM latency never delays the proxied reply. `LLMExtractor` also strips `<think>` blocks from the assistant text before building the SLM prompt. The system prompt and JSON schema allow `trait|directive|preference`: tone/character critiques become `trait`, hard rules `directive`, formatting/style requests `preference` (e.g. "be more terse", "stop apologizing", "give me unified diffs" are interaction updates, not concepts), linked from `User` via `prefers`/`demands`/`enforces`; a changed or contradicted rule must emit a `deprecated_edges` entry for the old edge.
- `config.py`: Frozen `Config` dataclass. Resolution per field: env var > `~/.config/cortext/config.json` > default. Keys: `decay_enabled` (bool, default `false`, `CORTEXT_DECAY_ENABLED`), `decay_half_life_days` (float, default `30.0`, `CORTEXT_DECAY_HALF_LIFE_DAYS`; fractional days allowed), `upstream_url`, `upstream_api_key`, `api_key`, `host`, `port`, `db_path`, `log_level`, `socket_path`, `extractor_model`, `extractor_url` (both default empty), `distance_threshold` (float, default `1.0`, max L2 distance for semantic matches), `dedup_distance_threshold` (float, default `0.45` ~ cosine 0.90, max L2 distance for merging a candidate entity into an existing one at ingestion; env `CORTEXT_DEDUP_DISTANCE_THRESHOLD`, config.json `dedup_distance_threshold`; passed by `daemon.build_app` to `DistillationEngine`) (env: `CORTEXT_<KEY>`). Defaults: host `127.0.0.1`, port `8088`, upstream `https://api.openai.com/v1`, `socket_path` empty. Transport detection (`effective_socket_path`, `is_socket_mode`, `get_bind_target`): explicit `socket_path` selects UDS; else UDS at `$XDG_RUNTIME_DIR/cortext/cortext.sock` when `XDG_RUNTIME_DIR` is set and host/port were not set via env or config.json (`tcp_explicit`, excluded from equality); else TCP. A malformed file is ignored on load. `save_config_value` writes atomically (temp file + `os.replace`, mode `0600`), creating the parent dir with mode `0700` and chmodding it to `0700` (guarded against `PermissionError`). Secret masking is performed by `cli.py` (`mask_secret`), not here. `persona_prompt` (str, default `""`, `CORTEXT_PERSONA_PROMPT`) is an optional bedrock persona anchor, passed by `daemon.build_app` to `ContextResolver(persona_prompt=...)`.
- `daemon.py`: Entrypoint (`python -m cortext.daemon`). `build_app` wires `DatabaseManager`, `SessionLedger`, `ContextResolver`, `create_app`. `main` loads config, starts logging, then serves in socket mode or TCP mode (Section 5). Socket lifecycle (ROB-1): `prepare_socket` creates the parent dir `0700` (the `chmod` is guarded against `PermissionError`, e.g. under `/tmp`) and removes a pre-existing path only if `stat.S_ISSOCK(os.stat(path).st_mode)` is true and a connect probe finds no live listener; a regular file (such as a database) or a live socket raises `RuntimeError` (the daemon exits with a message) and is never unlinked. `_bind_socket` pre-binds the listening socket under `os.umask(0o177)` (restoring the old umask afterwards), so it is never visible with Uvicorn's default `0o666`, and `_serve_uds` hands it to uvicorn via `server.serve(sockets=[sock])`; a follow-up `chmod 0600` remains as a belt-and-braces check. On shutdown the socket is closed and unlinked only if it is still a socket. TCP mode uses `uvicorn.run(host, port)`. uvicorn traps SIGINT/SIGTERM and runs the FastAPI lifespan: startup connects SQLite; shutdown drains distillation tasks, closes the HTTP client, closes SQLite.
- `proxy.py`: FastAPI streaming proxy: `GET /health` (open readiness probe) and `POST /v1/chat/completions`. Resolves a session delta from the last user message and prepends it to the first `system` **or `developer`** message (ROB-3; otherwise inserts a new `system` message at index 0). Streams SSE upstream responses through unchanged. Optional constant-time inbound Bearer auth on `/v1/*` (Section 4). Reads `X-Cortext-Allow-Private` for egress scoping. Session id: body `session_id` > `X-Session-Id` header > `default`. Schedules background distillation after a successful exchange. On upstream failure it rolls back the session ledger (Section 6); there is no automatic upstream retry, the client retries and receives the full context again. Streaming path: upstream requests send `Accept-Encoding: identity`, the body is relayed with `aiter_bytes()`, and collected SSE text is split on `\n` only. The `StreamingResponse` carries `background=BackgroundTask(upstream.aclose)` so the upstream connection is closed even if the client disconnects before iteration starts (ROB-2). `relay` catches `GeneratorExit`/`asyncio.CancelledError` (client disconnect): it calls `ledger.reset(session_id)`, runs `await asyncio.shield(upstream.aclose())` and re-raises, without distilling. A mid-stream upstream `httpx.HTTPError` (headers already committed) resets the ledger and yields an explicit SSE `data:` error event (`type: upstream_error`) instead of a silent EOF. A completed stream is distilled only if it has a `[DONE]` marker or a non-null `finish_reason` and no event carrying an `error` object; otherwise the ledger is reset and nothing is distilled. `_stream_text` considers only `choices` with `index == 0` (multi-choice responses, ROB-3) and strips `<think>...</think>` reasoning blocks (`common.strip_think`) from the assembled text. Background distillation runs under `asyncio.Semaphore(4)` (`MAX_CONCURRENT_DISTILLATIONS`), bounding concurrent extractions (ROB-5). A `session_id` longer than 128 characters is rejected with HTTP 400.
- `resolver.py`: `ContextResolver`. `match_entities` does an exact whole-word scan of entity names and `metadata.aliases` (casefolded), then a constituent-token fallback, then (only if an `embedder` is injected and fewer than `max_entities` matched) a vector-KNN tier via `db.find_similar_entities`. Matching invariant: Exact Whole-Word -> Constituent-Token -> Vector KNN; semantic hits only fill remaining slots, never displace lexical ones, are filtered by the same `allow_private` rule, and are skipped entirely (no embedding call) when the lexical tiers already fill `max_entities`. `gather` walks the graph 1 to 2 hops (`MAX_HOPS_LIMIT = 2`). `resolve` returns a markdown block of facts new to the session. Facts with confidence < 0.8 are tagged `[inferred, confidence: x.xx]`. Private entities are scoped out unless allowed (Section 4). Defaults: `max_entities=5`, `edge_limit=10`. Semantic matching uses sqlite-vec default **L2 (Euclidean)** distance, not cosine: unit vectors at cosine distance ~0.35 sit at L2 ~0.83, orthogonal noise at L2 >= 1.414. `distance_threshold` (default `1.0`, wired from `Config.distance_threshold` by `daemon.build_app`) keeps hits with `distance <= threshold`. **Numerical guards (ROB-5):** `effective_priority` returns the plain undecayed `confidence * weight` when decay is disabled or when `half_life_days` is non-finite (`inf`/`nan`) or `<= 0`, so it never raises `ZeroDivisionError` or returns `NaN`. **Personality Matrix recall:** `personality_entities` loads every active (non-private unless allowed) `trait`/`directive`/`preference` node on every turn irrespective of query match (capped at `MAX_PERSONALITY_ENTITIES`; nodes whose every edge is deprecated are skipped). `format_context_delta` partitions the session delta hierarchically: `[Persona Stance]` (traits, preceded by the `persona_prompt` anchor), `[Operational Directives]`, `[Interaction Preferences]`, then `[Working Memory]` (the existing `Entities:`/`Relations:` graph triples); empty sections are omitted, and with no personality section the output is the unchanged plain block. Edges touching personality nodes are not repeated under Working Memory. Personality node ids (and a sentinel id for the persona anchor) go through the same `SessionLedger.seen_entity_ids` as factual nodes, so each is injected once per session and omitted on later turns. **Reality Guard (COG-1):** `detect_discrepancies` inspects active edges between matched entities whose relation is attribute-like (`has_*`, or containing the word `equipped`, `runs`, `model`, `spec`, `color`, `type`, `engine`, `transmission`, `os`, `arch`, `version`) and compares spec classes in the target's name+summary with those in the query (case-insensitive, token-bounded): speed counts (`5-speed` vs `6-speed`), `manual` vs `automatic`/`auto transmission`, cylinders (`v6`/`i6`/`inline-6` vs `v8`/`v10`/`v12`), `intel`/`amd`/`arm`, `fedora`/`ubuntu`/`debian`, `diesel` vs `petrol`/`gasoline`. A category conflicts only when both sides state a value and share none. Each conflict renders under `[Reality Check - Attribute Discrepancy]` (per entity: stored fact `[relation] -> target`, the query's conflicting token, plus a closing instruction to clarify or challenge), placed directly under the `## Cortext Memory` header, above `[Persona Stance]`; with no conflict the section is omitted. It is stateless and does not touch the SessionLedger: a repeated contradictory query is flagged again even when the delta is otherwise empty. The proxy log adds `discrepancies=N` when non-zero.
- `distill.py`: `DistillationEngine.process_exchange`: sanitize, substantive-turn gate, heuristic extraction (or injected extractor), grounding, persistence, episode record. Failures are logged, never raised. Conversational forgetting: `heuristic_extract` detects explicit "forget/erase/scrub <Name>" and "delete entity/note/record <Name>" commands (never "don't forget") into `forgotten_entities`; `process_exchange` first resolves each name through `db.find_entity` (canonical name, then unambiguous `metadata.aliases`), calls `db.drop_entity`, evicts the id from the optional `SessionLedger`, logs `User-directed forgetting: dropped entity '<name>' (id=<n>)` at INFO, discards same-extraction entities/edges/deprecations that reference the forgotten names, and appends `forgotten=N` to the episode log line when non-zero. Enforces the edge requirement and constituent consolidation (Section 6). `strip_markdown_structure` removes heading lines and bold labels so formatting words never become entities. All token/stop-word rules live in `stopwords.py` (`distill.py` keeps no private stop-word list). Edge validity (non-empty fields, no self-loop, valid names, no secrets) is defined once in `_valid_edge` and shared by the edge-requirement check and edge persistence; heuristic and injected extractors (e.g. `LLMExtractor`) go through the same `process_exchange` pipeline. `<think>...</think>` blocks are stripped from the assistant text before sanitization and extraction, so reasoning tokens are never treated as factual assertions (ROB-3).
- `sanitize.py`: `sanitize_text` replaces matches with `[REDACTED_SECRET]` for: PEM private key blocks, URIs with embedded credentials (DB URIs), JWTs, `Bearer` tokens, GitHub (`ghp_`, `github_pat_`, `ghs_`, `gho_`, `ghu_`), OpenAI-style `sk-`, Stripe `sk_live_`, Slack `xox[bap]-`, Google `AIza`, AWS `AKIA`/`ASIA`, HuggingFace `hf_`, and unclosed PEM blocks (to end-of-string); bounded quantifiers and a 200,000-character input cap prevent ReDoS (Section 4). `is_secret_token` flags candidate entity names that are redaction-affected or are high-entropy: length >= 24, no whitespace, contains letters and digits, Shannon entropy >= 3.5 bits/char.
- `stopwords.py`: Stop-word and filler lists, `is_valid_entity_name` (rejects stop-words/fillers; short names allowed via whitelist), `name_tokens`. Also used by the resolver to skip single-word stop-word concepts. `is_valid_entity_name` accepts any descriptive or hyphenated name for `trait`/`directive`/`preference` (only names without a word character are rejected).
- `session.py`: `SessionLedger`: in-memory, per-session `seen_entity_ids` and `seen_edge_ids` (separate id spaces), idle TTL 3600 s, `filter_new` returns a `SessionDelta`, `reset`, `evict_expired`, `evict_entity(entity_id)` (removes an id from every session so a forgotten entity is treated as gone). Capped at `max_sessions=1000` (`DEFAULT_MAX_SESSIONS`, must be >= 1): `filter_new` re-inserts the active session at the most-recent end and, when a new session would exceed the cap, evicts the least recently used one (ROB-5). `session_id` is limited to 128 characters (`MAX_SESSION_ID_LEN`): `filter_new` raises `ValueError` and the proxy answers HTTP 400. Single event loop only; not persisted.
- `logging.py`: `cortext` logger tree. `RotatingFileHandler` (5 MiB, 2 backups) at `~/.local/share/cortext/cortext.log` (override `CORTEXT_LOG_PATH`). Directory forced to `0700`, log file to `0600` (re-applied after each rollover). Stderr stream only in debug on a TTY.
- `compactor.py`: `SessionCompactor(db, extractor_url, extractor_model, threshold_hours=24.0)`. `compact_session(session_id)` loads uncompacted episodes (returns immediately when none), sanitizes narratives, asks the local SLM (or a heuristic when `extractor_model` is empty) for `{"entity_summaries": [{"name", "summary"}], "session_summary"}`, updates matching `entities.summary` via `db.update_entity_summary` (provenance-gated; SLM at `model_inferred` 0.6, heuristic at 0.5), then calls `db.mark_episodes_compacted`. `compact_all(older_than_hours=None)` compacts eligible sessions sequentially and returns the count. It never raises. DB methods: `get_uncompacted_sessions(older_than_seconds)` (distinct session ids whose newest uncompacted episode is older than the cutoff), `get_session_episodes(session_id, uncompacted_only=True)`, `mark_episodes_compacted(ids)` (`compacted_at = CURRENT_TIMESTAMP`), `update_entity_summary(name, summary, origin, confidence)`. Config: `compaction_threshold_hours` (default `24.0`, `CORTEXT_COMPACTION_THRESHOLD_HOURS`). **Privacy (ROB-4):** `_entities` excludes private entities (`archetype == 'private'` or `metadata.private is True`) before the prompt is built, so private names and summaries are never sent to the SLM.
- `cli.py`: `cortext` operator tool (`[project.scripts]`), global `--db`. Commands: `stats`, `list [--archetype --limit]`, `inspect <name|id>`, `drop <name|id> [-y]`, `prune-stale [--confidence-below X]` (default 0.5, removes model_inferred facts), `compact [--hours FLOAT] [--session TEXT]` (compacts inactive sessions, or one named session regardless of age; prints `Compacted session 'X' (N episodes, M summaries updated)`), `config show|get|set` (`show` masks secrets), `logs [-n N]`. `cortext list --archetype trait|directive|preference` filters the personality nodes like any other archetype.

## 4. Security & Privacy Architecture
- **POSIX storage isolation:** data and log directories `0700`; DB, WAL, SHM, log files and `config.json` `0600`. Applied at runtime by `db.py`, `logging.py`, `config.py`, not left to umask.
- **Inbound auth:** if `CORTEXT_API_KEY` (or `api_key` in config.json) is non-empty, every `/v1` and `/v1/*` request must send `Authorization: Bearer <key>`. It is compared with `hmac.compare_digest` and failure returns 401 `authentication_error`. `/health` is always open. If the key is empty, auth is disabled. The inbound key is distinct from `CORTEXT_UPSTREAM_API_KEY`. The upstream key, when set, is the only credential sent upstream. The client's `Authorization` header is forwarded only when neither key is configured.
- **Ingestion defense:** query and response pass through `sanitize_text` before substantive-turn gating, extraction and `record_episode`, so redacted text is what is stored. Entity names and edge endpoints that satisfy `is_secret_token` are dropped. The entropy heuristic applies to candidate names/endpoints only; free text is covered by the regex patterns.
- **Egress guardrails:** an entity is private according to one predicate, `common.is_private(archetype, metadata)`: the archetype is `private` (case-insensitive, trimmed), or `metadata['private']` is `true`, `1`/`1.0`, or the string `"true"`/`"1"` (any case; `"false"` and `0` are not private). It **fails closed**: corrupt JSON, non-object JSON or undecodable metadata counts as private; only absent/blank metadata means "no flags". `resolver`, `compactor` and `distill` all use it, and `db.PRIVATE_ENTITY_SQL` is its SQL twin inside the subgraph CTE (a parity test keeps them identical). `DistillationEngine` never rewrites an existing private entity. Private entities, and edges touching them, are excluded from the delta and from graph traversal unless the request sends `X-Cortext-Allow-Private: true` (case-insensitive). The default is no private data to the LLM. The same filter is applied inside the recursive CTE of `get_entity_subgraph` before `LIMIT`, and `SessionCompactor` never sends private entities to the SLM.
- **Prompt-injection guards:** assistant output is untrusted. Entities and edges derived from a model response are clamped to `origin = model_inferred` and confidence <= `0.60` (`MODEL_CONFIDENCE`); `parse_extraction` whitelists fields so model-emitted `origin`/`confidence` are dropped. Assistant responses can never issue `forgotten_entities` or `deprecated_edges` (these come only from the user's query), and a forget executes only when the user's own prompt contains a forget command that names the target (user corroboration).
- **Secret patterns & ReDoS protection:** `sanitize_text` redacts PEM private-key blocks (including unclosed ones, to end-of-string), credentialed URIs, JWTs, `Bearer` tokens, GitHub (`ghp_`, `github_pat_`, `ghs_`, `gho_`, `ghu_`), OpenAI-style `sk-`, Stripe `sk_live_`, Slack `xox[bap]-`, Google `AIza`, AWS `AKIA` and STS `ASIA`, and HuggingFace `hf_` tokens. Regexes use bounded quantifiers (no polynomial backtracking in the URL-credentials pattern) and input is truncated to 200,000 characters before matching.
- **HTTP ingress hardening:** `POST /v1/chat/completions` requires `Content-Type: application/json` (HTTP 415 otherwise; invalid JSON or non-list `messages` is 400; `session_id` > 128 chars is 400). FastAPI `/docs`, `/redoc` and `/openapi.json` are disabled. The body is capped at 10 MiB (`proxy.MAX_REQUEST_BYTES`): HTTP 413 when `Content-Length` exceeds it or when a chunked body crosses it while being read; pathologically nested JSON (`RecursionError`) is 400, never 500.
- **No private-context laundering:** an exchange sent with `X-Cortext-Allow-Private: true` is never distilled (non-streaming and streaming), so private facts quoted in the reply cannot be copied into public, un-flagged entities. The skip is logged.
- **Log hygiene:** the "Incoming query" log line contains the query length and an 80-character preview of the *sanitized* query (sanitize first, then truncate).
- **Socket & filesystem isolation:** the UDS is pre-bound under `umask 0o177`, only dead sockets are ever unlinked, and config/data directories are forced to `0700` (Section 3, `daemon.py`/`config.py`).

## 5. Transport
- **Desktop mode (UDS):** zero-network local IPC at `$XDG_RUNTIME_DIR/cortext/cortext.sock` (mode `0600`, parent dir `0700`), or any path given by `CORTEXT_SOCKET_PATH`.
- **Server/container mode (TCP):** `CORTEXT_HOST:CORTEXT_PORT`, chosen whenever host or port is set explicitly or `XDG_RUNTIME_DIR` is absent. The Docker image sets `CORTEXT_HOST=0.0.0.0`, so it uses TCP.
- **TCP details:** Served by uvicorn on `CORTEXT_HOST:CORTEXT_PORT` (default `127.0.0.1:8088`). Use this for Docker/remote deployments, with `CORTEXT_API_KEY` set when binding beyond loopback. `daemon.warn_if_exposed` logs a `SECURITY` warning at startup when the TCP host is not loopback (`127.*`, `::1`, `localhost`) and no `api_key` is configured; it warns but does not refuse to start.
- **UDS details:** socket lifecycle is in the `daemon.py` entry (Section 3). systemd uses `RuntimeDirectory=cortext` and `%t/cortext` in `ReadWritePaths`.

## 6. Operational Invariants
- **Edge requirement:** a `model_inferred` entity persists only if it is an endpoint of at least one valid edge in the same extraction (valid = non-empty source/target/relation, not a self-loop, valid names, no secrets). Otherwise it is dropped. `user_explicit` entities are exempt.
- **Compaction:** only sessions whose newest uncompacted episode is older than the threshold are compacted (`--session` bypasses the age check). Episodes are never deleted, only stamped `compacted_at`, and are stamped only after the summary step succeeds, so a session is compacted at most once and retried if the SLM fails. Compaction summaries obey provenance: they never displace a higher-confidence summary, nor a `user_explicit` one at equal confidence, and keep the stored origin/confidence. SLM output is sanitized and capped at 300 chars per summary; unknown entity names are ignored.
- **Provenance:** extractions without attribution are `model_inferred` at confidence 0.6. On upsert, higher confidence wins and `user_explicit` is never displaced at equal confidence.
- **Upstream failure rollback:** since facts are marked seen when resolved, any upstream failure (connect/send error, status >= 400, body-read error, stream interrupted mid-relay) calls `ledger.reset(session_id)` so the next request replays the full context. Failed or interrupted exchanges are never distilled. Client disconnects and cancellations mid-stream, in-stream SSE `error` events, and streams that end without `[DONE]` or a `finish_reason` follow the same rule: `ledger.reset(session_id)`, no distillation; the upstream connection is always closed (`BackgroundTask(upstream.aclose)` plus a shielded `aclose` in `relay`), and a mid-stream `HTTPError` is surfaced to the client as an SSE error event.
- **Forgetting corroboration:** a conversational forget is executed only when the user's own prompt in that turn contains a forget command that names the target entity; `forgotten_entities` proposed by an assistant response or an extractor SLM that the prompt does not corroborate are ignored and logged.
- **Stream disconnect & mid-stream error rollback:** an exchange is distilled only if its stream completed normally (`[DONE]` or non-null `finish_reason`) with no in-stream `error` payload and no client disconnect; every other outcome resets the session ledger so the next request replays the full context.
- **Reasoning-block stripping:** `<think>`, `<thinking>`, `<thought>` and `<reasoning>` blocks (case-insensitive, multiline, closed only by their own tag; an unclosed block runs to the end). `_stream_text` also reads list-form `delta.content` (`[{"type": "text", "text": ...}]`, joined with no separator) instead of dropping the chunk. Stripped text never reaches distillation or extraction; it is removed in `_stream_text`, `DistillationEngine.process_exchange` and `LLMExtractor`. Only `choices[0]` (`index == 0`) contributes to streamed assistant text.
- **Private exclusion before `LIMIT`:** private entities are excluded inside the recursive CTE of `get_entity_subgraph`, before the SQL `LIMIT`, so they never consume hop/edge slots; the resolver's post-filter and the compactor's prompt filter are additional layers, not substitutes.
- **Bounded resources:** at most 4 background distillations run concurrently, the session ledger holds at most 1000 sessions (LRU eviction) and session ids are at most 128 characters.
- **Alias matching:** exact = casefolded whole-word match of the entity name or any `metadata.aliases` entry (word boundary enforced only on word-character edges, so `C++` matches). Constituent = whole-word match of a single token of a name/alias (>= 3 chars, not a stop/function word). Ranking: confidence desc, exact before constituent, first mention, id.
- **Constituent consolidation (write side):** a single-word candidate with no entity of its own that equals an alias or token of exactly one multi-word entity (`BMW` -> `BMW 540i`) refreshes that entity's `updated_at` instead of creating a node. Ambiguous matches are not consolidated.
- **Dedup / alias merge gate (write side):** before `DistillationEngine` inserts a candidate entity it calls `db.find_duplicate_entity`. A candidate equal (casefolded) to an existing entity name or `metadata.aliases` entry resolves to that entity; otherwise, when vectors are enabled, the nearest entity within `dedup_distance_threshold` (L2 <= 0.45) with the **same archetype** is the canonical entity (a `system` never merges into a `concept`). A merge inserts no row: the candidate name is appended to `metadata.aliases` (no duplicates), an empty summary is filled from the candidate, confidence/origin follow the provenance precedence above, and `updated_at` is bumped so `ContextResolver`'s alias scanner recognizes the alias on the next recall. Every edge in the same extraction that named the candidate is wired to the canonical entity id. Without sqlite-vec or an embedder only the exact/alias string check applies. An exact-name hit is a normal upsert, not a merge.
- **Edge deprecation (contradiction resolution):** `DistillationEngine` processes `deprecated_edges` after entities and active edges, mapping endpoints to canonical ids (names merged/consolidated this turn, else db alias resolution) and calling `db.deprecate_edge`; each deprecation logs at INFO. Episodes are never altered. `ContextResolver.gather` requests `active_only` subgraphs and also drops any edge with `weight <= 0.0`, `confidence < 0.2` or `metadata.deprecated is True`, so deprecated edges are never traversed or injected. The heuristic fallback detects basic negation (`I sold X`, `I no longer use X`, `I stopped using X`) as a `User -> X` deprecation; otherwise `deprecated_edges` is empty.
- **Temporal access decay & reinforcement:** `ContextResolver.resolve` calls `db.touch_access` for every entity and edge id gathered into the context (including facts already seen this session, so active knowledge stays reinforced); a touch failure is logged and never blocks recall. With `decay_enabled = false` (default) ranking is the legacy `confidence * weight` (entities: confidence first, then match tier/position) and nothing is pruned. With it enabled, `resolver.effective_priority` = `confidence * weight * decay_factor * frequency_factor`, where `delta_days = (now - (last_accessed_at or created_at)).total_seconds() / 86400.0` (edges fall back to `updated_at`), `decay_factor = 2.0 ** (-max(0.0, delta_days) / decay_half_life_days)` and `frequency_factor = min(1.5, 1.0 + 0.05 * access_count)` (entities have weight 1.0). Matched entities are sorted by effective priority (then match tier, first mention, id), subgraph edges by hop, then effective priority, and any entity or edge below `0.15` is pruned. Facts without a usable timestamp are treated as fresh.
- **Conversational forgetting:** user-directed forgetting is a permanent hard delete like `cortext drop`: `db.drop_entity(id)` removes the entity, every edge touching it and its `entity_embeddings` row (when vectors are active) in one WAL transaction. Names resolve by casefolded canonical name or an alias that identifies exactly one entity; an ambiguous or unknown name is a logged no-op that never raises, and the episode is still recorded. A forgotten entity (and its aliases) is never re-created or linked by the same extraction, and is evicted from active `SessionLedger` sessions (`DistillationEngine(ledger=...)`, wired by `daemon.build_app` and `proxy.create_app`). Only the user's explicit command triggers it; model-inferred forgetting is not supported.
- **Turn gating:** trivial exchanges (short greeting/acknowledgment queries without a fact assertion, empty or boilerplate replies) are not distilled.

## 7. Graceful Degradation & Diagnostics
- **Embedder fallback:** `embed.create_embedder()` returns a lazy `EmbeddingManager`, or `None` when `fastembed` is not installed (logs `[WARNING] [embed] fastembed unavailable; falling back to lexical-only matching.`). `daemon.build_app` passes it straight to `ContextResolver(..., embedder=...)`, so a `None` embedder means lexical-only mode. If the lazy import or model load fails (corrupt install, offline weights), `EmbeddingManager` logs the same warning once and raises `EmbeddingUnavailable` on every later call; the resolver treats that as "no semantic hits", `DatabaseManager` writes without an embedding, and `embed-backfill` exits 1 with a message.
- **sqlite-vec fallback:** if the extension fails to load, `DatabaseManager.connect` logs `[WARNING] [db] sqlite-vec extension failed to load; vector indexing disabled.`, skips creating `entity_embeddings`, and sets `vec_enabled = False`. Entities, edges and episodes work normally; embedding writes, auto-embedding, `find_similar_entities` (returns `[]`) and the resolver's semantic tier are skipped; `cortext drop` skips the vector delete; `embed-backfill` exits 1.
- **Compaction fallback:** if the extractor SLM is unreachable, errors, or returns unparseable JSON, `SessionCompactor` logs `[WARNING] [compactor]` and skips the session, leaving its episodes uncompacted; `cortext compact` prints a `Skipped session` line and still exits 0.
- **`cortext doctor`** (`cli.py`): prints a checklist (`[ok]`, `[warn]`, `[fail]`) for DB path and journal mode, sqlite-vec status, fastembed install and model cache (`$FASTEMBED_CACHE_PATH` or `<tmp>/fastembed_cache`), extractor SLM reachability (`GET {extractor_url}/models`, timeout 0.5 s; a failure is `[fail]` only if `extractor_model` is configured), and the active transport (UDS path or TCP host:port). It always exits 0.

## 8. Security Hardening (Phase 2)
- **Ingestion immunity (SEC-1):** assistant output is untrusted. `heuristic_extract` forces every entity/edge parsed from a response JSON block to `model_inferred` at confidence <= `MODEL_CONFIDENCE`, and ignores any `forgotten_entities`/`deprecated_edges` in it (they come only from the user's query). `parse_extraction` copies whitelisted fields only, so model-emitted `origin`/`confidence` are dropped. `DistillationEngine.process_exchange` executes a forget only when the user's prompt contains a forget command and mentions the target name.
- **Streaming (SEC-2):** streaming requests are sent upstream with `Accept-Encoding: identity`; chunks are relayed with `aiter_bytes()`; SSE text is split on `\n` only (never `splitlines()`).
- **Fail-open memory (SEC-3):** any exception from `resolver.resolve` is logged with `exc_info`, the session ledger is reset, and the request is forwarded without injected context.
- **Ingress (SEC-4):** `POST /v1/chat/completions` requires `Content-Type: application/json` (parameters like charset allowed), else HTTP 415. FastAPI `/docs`, `/redoc` and `/openapi.json` are disabled.
- **Sanitizer (SEC-5):** input is capped at 200,000 characters before regex processing; the URL-credentials pattern uses a lookbehind and bounded quantifiers (no polynomial backtracking). Extra patterns: Stripe `sk_live_`, Slack `xox[bap]-`, AWS `ASIA`, GitHub `ghs_`/`gho_`/`ghu_`, HuggingFace `hf_`, and unclosed PEM private-key blocks (redacted to end-of-string).
- **Config (SEC-6):** `load_config(strict=True)` (used by `daemon.main`) raises `ValueError` on unreadable/corrupt `config.json`, and the daemon exits with a configuration error; the CLI stays lenient. `Config.from_env` picks `env` (non-empty) then the file value whenever it is not `None`, so explicit `0`, `0.0` and `""` survive.

## 9. Operations & Desktop UI (Phase 4)

### Daemon operational modes
- **Silent (default):** `python3 -m cortext.daemon` (also the systemd `ExecStart`) prints nothing to the terminal. Cortext's structured logs and uvicorn's own logs (`uvicorn.config.LOGGING_CONFIG` is swapped for the run, then restored, to route them through `logging.uvicorn_log_handler`) go to the rotating `~/.local/share/cortext/cortext.log` (mode `0600`, dir `0700`; override with `CORTEXT_LOG_PATH`). Read it with `cortext logs -n N`.
- **Diagnostic:** `python3 -m cortext.daemon --diag` (alias `--debug`) or `cortext daemon --diag` forces DEBUG level and adds a stderr stream handler (colored by level when stderr is a TTY) while uvicorn keeps its default console output. The log file is still written. `cortext daemon` without the flag is the same silent mode in the foreground. `daemon.main(argv)` takes the arguments; with none it is silent.
- **systemd user service:** `packaging/systemd/cortext.service` runs `/usr/bin/env python3 -m cortext.daemon` against the user's own environment (`pip install --user`). Setup: create `~/.config/cortext` and `~/.local/share/cortext`, copy the unit to `~/.config/systemd/user/`, `systemctl --user daemon-reload`, then `systemctl --user enable --now cortext`. For troubleshooting, stop the service and run it with `--diag`. Socket and file POSIX modes (`0700`/`0600`) are unchanged in every mode.

### Model configuration (`model_default`)
- `config.json` key `model_default` (env `CORTEXT_MODEL_DEFAULT`, default `""`), set with `cortext config set model_default "gemini-3.6-flash"`; values are stripped. The daemon itself does not use it: it is the default model for clients.
- The GUI resolves its model in `ui.bridge.resolve_model`, first non-empty of: (1) explicit `Bridge(model=...)` argument, (2) `$CORTEXT_UI_MODEL`, (3) `Config.model_default`, (4) the fallback `bridge.DEFAULT_MODEL` (`gpt-4o-mini`). The footer reads `Bridge.modelName`, so it always shows the resolved model.

### Desktop UI (`src/cortext/ui/`)
- `app.py`: launcher, exposed as the `cortext-gui` console script (`cortext.ui.app:main`) and `python -m cortext.ui`. It creates a `QGuiApplication` (Basic Quick Controls style), builds one `Bridge`, registers it as the QML context property `bridge`, loads `qml/main.qml` in a `QQmlApplicationEngine` (a native Qt Quick window; exit code 1 if it fails to load), calls `bridge.checkConnection()` and runs the event loop. PySide6 is imported lazily inside `main`.
- `bridge.py`: `Bridge(QObject)` between QML and the daemon. Transport is httpx over the daemon's UNIX domain socket (`httpx.AsyncHTTPTransport(uds=...)`, base URL `http://cortext`), used only when `Config.effective_socket_path()` exists and is a socket; otherwise loopback TCP `http://host:port`. It sends `Authorization: Bearer` when `api_key` is set and an `X-Session-Id` header (`ui-<hex>`, regenerated by `newConversation`).
- **Threading model:** the GUI thread only touches QML. `sendMessage` and `checkConnection` run their coroutine on a daemon worker thread (`cortext-ui-io`) with its own `asyncio.run` loop. Results return as Qt signals (`chunkReceived`, `streamFinished`, `errorOccurred`, `statusChanged`, `busyChanged`) emitted on the worker and delivered to the GUI thread as queued connections. One turn at a time (`busy`, guarded by a lock). SSE is split on `\n` only; errors pop the unanswered user message from history.
- `qml/main.qml`: the chat window. A slim header row (with the diagnostics toggle), the transcript, the input bar and the status footer (`bridge.status`, `bridge.modelName`), plus the right-hand diagnostics drawer.

### UI shortcuts
| Key | Action |
| --- | --- |
| `Enter` / `Shift+Enter` | Send / newline |
| `Ctrl+L` | New conversation: `Bridge.newConversation()` aborts any running turn, clears history, rotates `session_id` (`ui-<hex>`) and emits `conversationReset`, which clears the transcript |
| `Esc` | Busy: `Bridge.abort()` cancels the stream (partial text is kept and marked `[stopped]`, and it enters history). Idle: clears the input |
| `Up` / `Down` | In an empty input (or while already browsing), step through up to 100 recently sent prompts and slash commands (`historyPrevious`/`historyNext`); `Down` past the newest restores an empty input |
| `Ctrl+D` | Toggle the diagnostics drawer (also the small header icon) |

Abort works by cancelling the asyncio task on the worker thread (`loop.call_soon_threadsafe(task.cancel)`); closing the HTTP stream lets the daemon see the disconnect and reset the session ledger as for any client disconnect. Each turn carries a generation counter, so a turn aborted by a reset never writes into the new session's history.

### Local slash commands
Handled by `Bridge.runCommand` (parsed by `parse_command`: one leading `/word` only, so `/etc/hosts ...` is a normal prompt). They are never sent to the daemon or upstream and are not added to chat history. Feedback is shown as a dim note in the transcript.
- `/new`: same as `Ctrl+L`.
- `/private on|off`: adds the header `X-Cortext-Allow-Private: true` to subsequent requests (off by default, per Section 4); the header row shows `private` while on. Without an argument it reports the state.
- `/model <name>`: switches the model for subsequent requests; the footer and drawer follow (`modelChanged`). Without an argument it reports the current model.
- `/onboard`: resets the session like `/new`, flags it onboarding (`X-Cortext-Mode: onboarding` on its requests until the next `/new`/`Ctrl+L`) and immediately sends a synthetic trigger turn so Cortext opens the conversation; the trigger stays in history only for the upstream call.
- `/help` lists them; an unknown `/word` reports an error locally.

### Onboarding mode (COG-2, context resolution)
After `resolver.resolve`, `proxy.py` decides whether the session is an onboarding session: the request carries `X-Cortext-Mode: onboarding` (sent by `/onboard`), the session id was flagged earlier (an in-memory, bounded set, so later turns without the header stay in onboarding), or **Day Zero**: the DB holds 0 `person` entities. The directive, with ambient host specs, is prepended to the system delta; the header also seeds the operator anchor, while Day Zero only flags the session (Model B records people organically). Resolution failures fail open with no directive. `SessionLedger` is untouched, and distillation runs as usual on every turn except the synthetic `/onboard` trigger prompt.

### Diagnostics drawer
Hidden by default; a 280 px panel on the right (animated) showing `Bridge.diagnostics` (a `QVariantMap` refreshed on `diagnosticsChanged`): session id, model, transport (`unix:<socket path>` or `tcp:host:port`, from `Bridge.transport`), connection status, private-context state and the latest turn: outcome (`ok`/`error`/`aborted`), prompt characters, reply characters, time to first token and total round-trip latency (ms, from `time.perf_counter`). Values are selectable text.

### Rendering & window state
- Assistant replies are split by `split_markdown` on ``` fences (`Bridge.segments`): prose renders as Markdown, fenced code in a monospace block with a darker tinted background, border and optional language label. An unclosed fence during streaming renders as code until it closes.
- Window size persists across launches via `QSettings("cortext", "cortext-gui")` (native per-user location). `width`/`height` (keys `window/width`, `window/height`) are saved by `app.save_size` on every resize (debounced 300 ms) and on `aboutToQuit`, each followed by `settings.sync()` for an immediate disk flush. `app.restore_size` re-applies them clamped to a minimum of 480x500 (invalid values are ignored). This is the Wayland-safe part: compositors (e.g. KDE Plasma 6) forbid client-side absolute positioning, so size is the only geometry guaranteed to persist.
- The `(x, y)` position (`window/geometry`) is restored by `app.restore_geometry` only when the Qt platform is not `wayland`, ignoring values below the minimum size or fully off every attached screen; any exception while positioning is swallowed, so a rejected request never warns or fails. This is UI state only; it does not touch `config.json` or the daemon.
- Stream-abort resilience: `Bridge._stream` treats `asyncio.CancelledError` as a clean `[stopped]` abort, `httpx.HTTPError` as an error, and any other exception as an error (or a silent abort when `Esc` was pressed); `abort()` tolerates an already-closed event loop; the worker thread target catches `CancelledError`, `httpx.HTTPError` and `Exception` and always clears loop state and runs `on_done`, so an abort can never crash the Qt runtime or leave the input busy.
- None of this changes the transport: the socket path, the `0700`/`0600` modes and the daemon contract are untouched.
