# Strand Architecture Specification

## 1. Role & Identity
Strand is a sovereign, local, headless cognitive working-memory daemon for Linux.
It intercepts `/v1/chat/completions` requests from local frontends (Aether OmniBar, CLI pipes, editors), resolves relevant entity subgraphs from an embedded SQLite graph, injects a deduplicated context delta into the prompt, and proxies the call to a chosen frontier LLM.

Permanent invariants and non-goals live in `CONSTRAINTS.md`; this document describes what is built.

## 2. Storage Schema (`~/.config/strand/memory.db`)

_Permissions:_ `0700` applies only to Strand-managed directories named `strand`; a `memory.db` placed in `$HOME` or another unmanaged directory leaves that parent untouched and gets `0600` on the DB, WAL and SHM files (see Section 4, SEC-PERM-001). Embedding model weights are not stored in the DB: they live in the isolated `~/.cache/strand/fastembed` (`0700`, Section 4, SEC-CACHE-003).
Using `aiosqlite` and `sqlite-vec`:

1. `entities`:
   - `id` INTEGER PRIMARY KEY AUTOINCREMENT
   - `name` TEXT UNIQUE NOT NULL
   - `archetype` TEXT NOT NULL (person, project, system, vehicle, concept; Personality Matrix: trait, directive, preference, see below)
   - `summary` TEXT DEFAULT ''
   - `metadata` JSON DEFAULT '{}'
   - `origin` TEXT NOT NULL DEFAULT 'user_explicit' ('user_explicit', 'model_inferred', 'system')
   - `confidence` REAL NOT NULL DEFAULT 1.0 (0.0-1.0; higher confidence wins on upsert, user_explicit is never displaced at equal confidence; resolver tags < 0.8 as `[inferred]`)
   - `created_at`, `updated_at` DATETIME
   - `access_count` INTEGER NOT NULL DEFAULT 0 (times recalled into a context delta; migrated onto older DBs)
   - `last_accessed_at` DATETIME (NULL until first recall; set by `touch_access`)

2. `edges`:
   - `id` INTEGER PRIMARY KEY AUTOINCREMENT
   - `source_id` INTEGER NOT NULL (FK -> entities.id)
   - `target_id` INTEGER NOT NULL (FK -> entities.id)
   - `relation` TEXT NOT NULL
   - `weight` REAL NOT NULL DEFAULT 1.0
   - `metadata` JSON DEFAULT '{}'
   - `origin` TEXT NOT NULL DEFAULT 'user_explicit' ('user_explicit', 'model_inferred', 'system')
   - `confidence` REAL NOT NULL DEFAULT 1.0 (0.0-1.0; higher confidence wins on upsert, user_explicit is never displaced at equal confidence; resolver tags < 0.8 as `[inferred]`)
   - `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP (migrated onto older DBs; bumped on deprecation and winning upserts)
   - `access_count` INTEGER NOT NULL DEFAULT 0 and `last_accessed_at` DATETIME (same semantics as on entities; migrated onto older DBs)
   - UNIQUE(source_id, target_id, relation)
   - Deprecation: a severed edge is never deleted; it keeps its row with `weight = 0.0`, `confidence = 0.0`, `metadata.deprecated = true` and `metadata.deprecation_reason`.

3. `episodes`:
   - `id` INTEGER PRIMARY KEY AUTOINCREMENT
   - `timestamp` REAL NOT NULL
   - `session_id` TEXT NOT NULL
   - `narrative` TEXT NOT NULL
   - `extracted_entities` JSON DEFAULT '[]'
   - `compacted_at` DATETIME (NULL until session compaction processes the episode; migrated onto older DBs)

4. `entity_embeddings`:
   - `entity_id` INTEGER PRIMARY KEY (vec0 virtual table, float[384]); written by `upsert_entity(embedding=...)`, queried by `find_similar_entities` (KNN, L2 distance) for the resolver's semantic tier, deleted with the entity.

### Personality Matrix archetypes
Three further `entities.archetype` values form an adaptive Personality Matrix. No table or column changes: they are ordinary rows in `entities` and `edges`, so confidence/origin precedence, deprecation, forgetting, privacy and SessionLedger deduplication apply unchanged.
- `trait`: internal character, emotional stance and demeanor (e.g. "Sovereign systems peer, dry wit, unhurried, calm").
- `directive`: inflexible behavioral rules and invariants (e.g. "Never apologize or use conversational filler").
- `preference`: stylistic output formats (e.g. "Provide code updates as unified git diffs", "Torque specs in Nm").
They are linked from the `User` entity by `prefers` (preference), `demands` (directive) or `enforces` (trait / standing rule) edges. A changed or contradicted rule is retired by deprecating its edge (`deprecated_edges`); a personality node with edges but none live is superseded and no longer recalled.

**Critique deprecation & permanence guardrail (OBS-POL-005 Phase 1).** Model B only treats a behavioral critique as a standing change when it carries an explicit permanence marker ("from now on", "always", "never", "stop doing X", "switch to Y", "going forward"). Transient steering ("right now", "just for this", "give me ...") creates no directive and deprecates nothing. A permanent correction emits the obsolete rule in `deprecated_edges` and the replacement as an active `directive`/`preference` entity linked to the operator (`model_inferred` unless the user stated it explicitly). Deprecation severs edges only (`weight 0.0`, `confidence 0.0`, `metadata.deprecated = true`); entity nodes, including `user_explicit` ones, are never deleted, and repeats are idempotent.

## 3. Module Directory (`src/strand/`)
- `common.py`: dependency-free leaf module (imports nothing from `strand`): shared constants (`EMBEDDING_DIM`, `MIN_EDGE_CONFIDENCE`, `MODEL_CONFIDENCE`, `MAX_SUMMARY_LEN`, `MAX_NARRATIVE_LEN`) and shared helpers (`extract_json`, `load_metadata` (malformed JSON yields `{}`), `aliases_of`, `clean_text`, `truncate`, `strip_think`: removes case-insensitive, multiline `<think>`, `<thinking>`, `<thought>` and `<reasoning>` blocks, each closed only by its own tag, an unclosed block running to the end of the text; `is_private(archetype, metadata)`: the single privacy predicate, see Section 4). It also owns the archetype sets `FACTUAL_ARCHETYPES`, `PERSONALITY_ARCHETYPES` (`trait`, `directive`, `preference`) and `VALID_ARCHETYPES` (their union, imported by `distill.py`).
- `schema.py`: sole home of DDL (`SCHEMA_SQL`, `VEC_SCHEMA_SQL`), schema setup and column migrations: `run_migrations(conn, vec_enabled)` is called by `DatabaseManager.connect`. When `vec_enabled`, it also runs `ORPHAN_VECTOR_SWEEP_SQL` (`DELETE FROM entity_embeddings WHERE entity_id NOT IN (SELECT id FROM entities)`), so vectors left behind by historical drops are removed on every connect.
- `host.py`: dependency-free leaf module (imports nothing from `strand`). `get_host_context()` returns `user`, `hostname`, `os` (`platform.freedesktop_os_release()` PRETTY_NAME, falling back to `platform.platform()`), `desktop`/`session` (`XDG_CURRENT_DESKTOP`/`XDG_SESSION_TYPE`), `cpu` (`/proc/cpuinfo` model name) and `ram_gb` (`/proc/meminfo` MemTotal); unreadable `/proc` yields `''`/`0.0`. `format_host_context` renders it on one line.
- `onboarding.py`: COG-2 grounding. `seed_operator_anchor(db, host_info) -> (user_id, host_id)` upserts the operator `person` (capitalized user name, alias `User`) and the `system` host and links them `(User) --[operates_host]--> (Host)` (weight 1.0, confidence 1.0, `user_explicit`); an existing operator is returned without being overwritten, so it is idempotent. The proxy no longer calls it (nothing is seeded from `$USER`). `count_operators(db)` counts `user_explicit` persons, `reanchor_generic_user(db)` folds a generic `User` node into the named operator, and `onboarding_directive(host_info, mode, first_turn, turn, telemetry_decision)` builds the `[Onboarding Directive: Grounding & Resonance]` block (Day Zero or Intent Triage). Day Zero arc: Turn 1 opening line only (asks the preferred name; `$USER` is no longer prohibited outright: the directive says not to reflexively default to it, but if the operator is coy or indifferent Strand may offer a cleaned-up name derived from the account name, e.g. "Alice", and ask whether it works); Turn 2/3 name greeting, hostname note, two-sentence mission and the domain-agnostic question "What do you usually find yourself working on, creating, or exploring at this computer?"; Turn 4/5 the **telemetry gate** question (`TELEMETRY_GATE_QUESTION`: "I keep things private by default—I don't review your local computer's details unless you want me to. Should I check out your machine specs, or keep that strictly on-demand?") with opt-in/decline handling, not repeated once `telemetry_decision` is known. `telemetry_preference(db)` reads the Model B edge `(<Operator>) --[prefers]--> (Host Telemetry Enabled | Host Telemetry On-Demand)` (no schema change). After each onboarding-session distillation the proxy applies it: `SessionLedger.set_allow_host_telemetry(session_id, choice)` (next turn carries or withholds specs) and `save_config_value("enable_host_telemetry", choice)` (atomic, `0600`); an unchanged choice is not re-written.
- `db.py`: `DatabaseManager` (aiosqlite). Focuses purely on connection lifecycle, PRAGMAs, query execution, transactions and graph traversal; DDL, schema setup and migrations live in `schema.py`. Opens the DB, loads `sqlite-vec`, applies `PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`, then delegates to `schema.run_migrations`. Exposes the public `transaction()` async context manager (serialized writer; commit/rollback). Enforces POSIX modes at runtime: parent dir `0700`, DB/`-wal`/`-shm` files `0600` (chmod errors from non-owners are ignored). Provides `touch_access(entity_ids, edge_ids)` (one transaction; `access_count += 1`, `last_accessed_at = CURRENT_TIMESTAMP`; duplicate ids count once, empty lists are a no-op), `deprecate_edge(source, target, relation, reason="deprecated")` (entity ids or names; canonical names and `metadata.aliases` resolve; relation casefolded; sets weight/confidence 0.0 and `metadata.deprecated`/`deprecation_reason`, bumps `updated_at`, keeps the row; returns False when no active matching edge exists; a later winning `upsert_edge` of the same triple revives it), `get_entity_subgraph(..., active_only=False)` (when true, deprecated edges are neither returned nor traversed; row metadata is parsed with `load_metadata`, so corrupt JSON yields `{}`), `upsert_entity` (an optional 384-float embedding replaces the row in `entity_embeddings`, only when the assertion wins on provenance), `upsert_edge` (confidence/origin precedence), `find_similar_entities(query_embedding, limit=5, distance_threshold=1.0)` (sqlite-vec KNN, L2 distance: `WHERE embedding MATCH ? AND k = ? ORDER BY distance`, keeps `distance <= threshold`, returns entity ids nearest first), `find_duplicate_entity(name, archetype, summary, distance_threshold=0.45)` (case-insensitive exact name/`metadata.aliases` match, then vector KNN restricted to the same archetype; string-only when vectors or the embedder are unavailable), `merge_entity_alias(id, alias, summary, origin, confidence)` (appends a de-duplicated alias, fills an empty summary, applies confidence by provenance precedence, always bumps `updated_at`), `upsert_entity_deduped` (find + merge, else plain `upsert_entity`), `get_entity_subgraph`, `record_episode`. Dropping an entity (`cli.py`) also deletes its `entity_embeddings` row. **Subgraph privacy (ROB-4):** the recursive CTE in `get_entity_subgraph` joins `entities` and refuses to walk into private entities (`archetype = 'private'` or `metadata.private` true) inside the walk itself, i.e. before the SQL `LIMIT`, so hidden nodes cannot consume hop or edge quota and crowd out visible facts.
- `embed.py`: `Embedder` protocol (`embed(text) -> list[float]`) and `EmbeddingManager`, a `fastembed.TextEmbedding` wrapper (default `BAAI/bge-small-en-v1.5`, 384 dims, matching `entity_embeddings`). `fastembed` is imported and the model built lazily on first `embed`, so imports, the CLI and tests never pay load cost. A `model_factory` or any custom `Embedder` can be injected for offline tests; wrong-dimension output raises `ValueError`.
- **Embedder wiring:** `daemon.build_app` builds one lazy `EmbeddingManager` and shares it with `ContextResolver(..., embedder=...)` (semantic tier) and `DatabaseManager(..., embedder=...)`, so daemon startup stays fast. When a `DatabaseManager` has an embedder and `upsert_entity` gets `embedding=None`, it embeds `f"{name}: {summary}"` (just `name` when the summary is empty; see `db.embedding_text`) off the event loop; an embedder failure is logged and never blocks the write. An explicit `embedding` always wins. `strand embed-backfill` (`cli.py`) embeds every entity with no `entity_embeddings` row using the same text format and reports the count; re-running it is a no-op.
- `extractors.py`: Model B. `LLMExtractor(base_url, model_name, api_key="ollama")` is an async `Extractor` (`(query, response) -> extraction`) for `DistillationEngine`. It POSTs to a local OpenAI-compatible `{base_url}/chat/completions` (Ollama, vLLM) with a concise system prompt demanding strict JSON: `entities` (name, archetype, summary) , `edges` (source, target, relation) and `deprecated_edges` (source, target, relation, reason; emitted only when the user explicitly says a relationship ended, was replaced, sold, stopped or invalidated) plus optional `forgotten_entities` (list of names; emitted only when the user explicitly commands the system to forget, delete, scrub or erase an entity, and never also listed as an entity or edge endpoint). `parse_extraction` defaults `forgotten_entities` to `[]` when missing or malformed. `parse_extraction` tolerates code fences and surrounding prose, drops malformed items, and any transport error, non-2xx status or unparsable JSON yields empty lists, so the exchange is still recorded as an episode. Output flows through the normal ingestion defenses (sanitization, grounding, provenance: `model_inferred` at 0.6, edge requirement). `daemon.build_app` uses it only when `extractor_model` is set (URL defaults to `http://127.0.0.1:11434/v1`); otherwise `heuristic_extract` stays the default. Distillation is a background task, so SLM latency never delays the proxied reply. `LLMExtractor` also strips `<think>` blocks from the assistant text before building the SLM prompt. The system prompt and JSON schema allow `trait|directive|preference`: tone/character critiques become `trait`, hard rules `directive`, formatting/style requests `preference` (e.g. "be more terse", "stop apologizing", "give me unified diffs" are interaction updates, not concepts), linked from `User` via `prefers`/`demands`/`enforces`; a changed or contradicted rule must emit a `deprecated_edges` entry for the old edge. **Direct predicate invariant:** traits, concerns and preferences attach directly from the subject to the concrete entity (`(User) --[prefers]--> (AWD)`); the prompt forbids intermediate containers such as `User's Preference`, `User's Concern` or `User Settings`, and `parse_extraction` enforces it via `collapse_containers`, which drops such grouping entities (and edges into them) and re-attaches their outgoing edges to the subject (generic relations `has`/`includes`/... become `prefers`/`concerned_about`/`enforces`).
- `config.py`: Frozen `Config` dataclass. Resolution per field: env var > `~/.config/strand/config.json` > default. Keys: `decay_enabled` (bool, default `true` = Balanced 30d, `STRAND_DECAY_ENABLED`), `decay_half_life_days` (float, default `30.0`, `STRAND_DECAY_HALF_LIFE_DAYS`; fractional days allowed; `load_config(strict=True)` and `config set` reject `<= 0`, `nan` and `inf` with a ValueError, and `resolver.effective_priority` falls back to undecayed `confidence * weight` on an invalid value), `upstream_url`, `upstream_api_key`, `api_key`, `host`, `port`, `db_path`, `log_level`, `socket_path`, `extractor_model`, `extractor_url` (both default empty), `distance_threshold` (float, default `1.0`, max L2 distance for semantic matches), `dedup_distance_threshold` (float, default `0.45` ~ cosine 0.90, max L2 distance for merging a candidate entity into an existing one at ingestion; env `STRAND_DEDUP_DISTANCE_THRESHOLD`, config.json `dedup_distance_threshold`; passed by `daemon.build_app` to `DistillationEngine`) (env: `STRAND_<KEY>`). Defaults: host `127.0.0.1`, port `8088`, upstream `https://api.openai.com/v1`, `socket_path` empty. Transport detection (`effective_socket_path`, `is_socket_mode`, `get_bind_target`): explicit `socket_path` selects UDS; else UDS at `$XDG_RUNTIME_DIR/strand/strand.sock` when `XDG_RUNTIME_DIR` is set and host/port were not set via env or config.json (`tcp_explicit`, excluded from equality); else TCP. A malformed file is ignored on load. `save_config_value` writes atomically (temp file + `os.replace`, mode `0600`), creating the parent dir with mode `0700` and chmodding it to `0700` (guarded against `PermissionError`). Secret masking is performed by `cli.py` (`mask_secret`), not here. `persona_prompt` (str, default `""`, `STRAND_PERSONA_PROMPT`) is an optional bedrock persona anchor, passed by `daemon.build_app` to `ContextResolver(persona_prompt=...)`.
- `daemon.py`: Entrypoint (`python -m strand.daemon`). `build_app` wires `DatabaseManager`, `SessionLedger`, `ContextResolver`, `create_app`. `main` loads config, starts logging, then serves in socket mode or TCP mode (Section 5). Socket lifecycle (ROB-1): `prepare_socket` creates the parent dir `0700` (the `chmod` is guarded against `PermissionError`, e.g. under `/tmp`) and removes a pre-existing path only if `stat.S_ISSOCK(os.stat(path).st_mode)` is true and a connect probe finds no live listener; a regular file (such as a database) or a live socket raises `RuntimeError` (the daemon exits with a message) and is never unlinked. `_bind_socket` pre-binds the listening socket under `os.umask(0o177)` (restoring the old umask afterwards), so it is never visible with Uvicorn's default `0o666`, and `_serve_uds` hands it to uvicorn via `server.serve(sockets=[sock])`; a follow-up `chmod 0600` remains as a belt-and-braces check. On shutdown the socket is closed and unlinked only if it is still a socket. TCP mode uses `uvicorn.run(host, port)`. uvicorn traps SIGINT/SIGTERM and runs the FastAPI lifespan: startup connects SQLite; shutdown drains distillation tasks, closes the HTTP client, closes SQLite.
- `proxy.py`: FastAPI streaming proxy: `GET /health` (open readiness probe) and `POST /v1/chat/completions`. Resolves a session delta from the last user message and prepends it to the first `system` **or `developer`** message (ROB-3; otherwise inserts a new `system` message at index 0). Streams SSE upstream responses through unchanged. Optional constant-time inbound Bearer auth on `/v1/*` (Section 4). Reads `X-Strand-Allow-Private` for egress scoping. Session id: body `session_id` > `X-Session-Id` header > `default`. Schedules background distillation after a successful exchange. On upstream failure it rolls back the session ledger (Section 6); there is no automatic upstream retry, the client retries and receives the full context again. Streaming path: upstream requests send `Accept-Encoding: identity`, the body is relayed with `aiter_bytes()`, and collected SSE text is split on `\n` only. The `StreamingResponse` carries `background=BackgroundTask(upstream.aclose)` so the upstream connection is closed even if the client disconnects before iteration starts (ROB-2). `relay` catches `GeneratorExit`/`asyncio.CancelledError` (client disconnect): it calls `ledger.reset(session_id)`, runs `await asyncio.shield(upstream.aclose())` and re-raises, without distilling. A mid-stream upstream `httpx.HTTPError` (headers already committed) resets the ledger and yields an explicit SSE `data:` error event (`type: upstream_error`) instead of a silent EOF. A completed stream is distilled only if it has a `[DONE]` marker or a non-null `finish_reason` and no event carrying an `error` object; otherwise the ledger is reset and nothing is distilled. `_stream_text` considers only `choices` with `index == 0` (multi-choice responses, ROB-3) and strips `<think>...</think>` reasoning blocks (`common.strip_think`) from the assembled text. Background distillation runs under `asyncio.Semaphore(4)` (`MAX_CONCURRENT_DISTILLATIONS`), bounding concurrent extractions (ROB-5). A `session_id` longer than 128 characters is rejected with HTTP 400. **Host injection (SEC-PRIV-002):** when an onboarding directive is built, `get_host_context()` output is passed through `host.redact_host_context` (keeps only `user` and `hostname`) unless `config.enable_host_telemetry is True` or `SessionLedger.allow_host_telemetry(session_id)` is true; the full specs are then included as before. The session override is an in-memory flag on `SessionState` (`SessionLedger.set_allow_host_telemetry` / `allow_host_telemetry`), set mid-session by the request header `X-Strand-Host-Telemetry: true|false` (conversational opt-in without a daemon restart); it is dropped when the session is reset or expires. The same flag is also set by the conversational onboarding opt-in/decline described under `onboarding.py` above.
- `resolver.py`: `ContextResolver`. **In-process cache (PERF-RES-001):** `match_entities` reads an immutable snapshot of the entity table (rows, precomputed casefolded name/alias terms, tokens and the private id set) cached on the resolver and keyed by `(db.write_version, PRAGMA data_version)`. `DatabaseManager.write_version` is a monotonic int bumped when any graph-writing `transaction()` ends (`upsert_entity`, `update_entity_metadata`, `drop_entity`, `upsert_edge`, `deprecate_edge`, alias merges, pruning, CLI deletes); `touch_access`, `record_episode` and `mark_episodes_compacted` do not bump it. A matching key reuses the snapshot with no `entities` scan; any change (or a commit by another process, seen through `data_version`) rebuilds it, so marking private or dropping takes effect on the next request. Private ids are fetched with `PRIVATE_ENTITY_SQL`, `allow_private=False` matches only the snapshot's public view (fail-closed), and the lexical matching and snapshot build run in `asyncio.to_thread`. With `decay_enabled` the snapshot is rebuilt per request. `match_entities` does an exact whole-word scan of entity names and `metadata.aliases` (casefolded), then a constituent-token fallback, then (only if an `embedder` is injected and fewer than `max_entities` matched) a vector-KNN tier via `db.find_similar_entities`. Matching invariant: Exact Whole-Word -> Constituent-Token -> Vector KNN; semantic hits only fill remaining slots, never displace lexical ones, are filtered by the same `allow_private` rule, and are skipped entirely (no embedding call) when the lexical tiers already fill `max_entities`. `gather` walks the graph 1 to 2 hops (`MAX_HOPS_LIMIT = 2`). `resolve` returns a markdown block of facts new to the session. Facts with confidence < 0.8 are tagged `[inferred, confidence: x.xx]`. Private entities are scoped out unless allowed (Section 4). **Fail-closed defaults (SEC-PRIV-003):** every resolver entry point (`match_entities`, `gather`, `recent_continuity`, `personality_entities`, `resolve`) defaults to `allow_private=False`; callers must pass `allow_private=True` explicitly, and `resolve()` always forwards the flag. Defaults: `max_entities=5`, `edge_limit=10`. Semantic matching uses sqlite-vec default **L2 (Euclidean)** distance, not cosine: unit vectors at cosine distance ~0.35 sit at L2 ~0.83, orthogonal noise at L2 >= 1.414. `distance_threshold` (default `1.0`, wired from `Config.distance_threshold` by `daemon.build_app`) keeps hits with `distance <= threshold`. **Numerical guards (ROB-5):** `effective_priority` returns the plain undecayed `confidence * weight` when decay is disabled or when `half_life_days` is non-finite (`inf`/`nan`) or `<= 0`, so it never raises `ZeroDivisionError` or returns `NaN`. **Personality Matrix recall:** `personality_entities` loads every active (non-private unless allowed) `trait`/`directive`/`preference` node on every turn irrespective of query match (capped at `MAX_PERSONALITY_ENTITIES`; nodes whose every edge is deprecated are skipped). `format_context_delta` partitions the session delta hierarchically: `[Persona Stance]` (traits, preceded by the `persona_prompt` anchor), `[Operational Directives]`, `[Interaction Preferences]`, then `[Working Memory]` (the existing `Entities:`/`Relations:` graph triples); empty sections are omitted, and with no personality section the output is the unchanged plain block. Edges touching personality nodes are not repeated under Working Memory. Personality node ids (and a sentinel id for the persona anchor) go through the same `SessionLedger.seen_entity_ids` as factual nodes, so each is injected once per session and omitted on later turns. **Bedrock Invariant & Persona Precedence (OBS-POL-005 Part 1):** `common.BEDROCK_INVARIANT` is the permanent identity text (sovereign, local-first cognitive companion; authentic, technically rigorous, direct; never apologize, no conversational filler). It is tracked in the ledger by the sentinel `BEDROCK_ID = -2` (the persona anchor keeps `PERSONA_ANCHOR_ID = -1`) and rendered directly under the `## Strand Memory` header. Precedence: (1) `BEDROCK_INVARIANT` is always emitted across all prompt envelopes (whenever any stance is emitted, on Turn 1 of each session). (2) If active, non-deprecated operator `trait`/`directive`/`preference` nodes exist in SQLite, they form the dynamic stance and suppress `config.persona_prompt`. (3) If zero active directives/traits exist (cold boot, or all superseded/deprecated), `config.persona_prompt` is restored as the fallback baseline under `[Persona Stance]`. (4) `SessionLedger` deduplication marks the dynamic directives (and the bedrock and anchor sentinels) as seen, so they are suppressed on Turn 2+ of the same session (0-token ongoing tax). **Reality Guard (COG-1):** `detect_discrepancies` inspects active edges between matched entities whose relation is attribute-like (`has_*`, or containing the word `equipped`, `runs`, `model`, `spec`, `color`, `type`, `engine`, `transmission`, `os`, `arch`, `version`) and compares spec classes in the target's name+summary with those in the query (case-insensitive, token-bounded): speed counts (`5-speed` vs `6-speed`), `manual` vs `automatic`/`auto transmission`, cylinders (`v6`/`i6`/`inline-6` vs `v8`/`v10`/`v12`), `intel`/`amd`/`arm`, `fedora`/`ubuntu`/`debian`, `diesel` vs `petrol`/`gasoline`. A category conflicts only when both sides state a value and share none. Each conflict renders under `[Reality Check - Attribute Discrepancy]` (per entity: stored fact `[relation] -> target`, the query's conflicting token, plus a closing instruction to clarify or challenge), placed directly under the `## Strand Memory` header, above `[Persona Stance]`; with no conflict the section is omitted. It is stateless and does not touch the SessionLedger: a repeated contradictory query is flagged again even when the delta is otherwise empty. The proxy log adds `discrepancies=N` when non-zero.
- `distill.py`: `DistillationEngine.process_exchange`: sanitize, substantive-turn gate, heuristic extraction (or injected extractor), grounding, persistence, episode record. Failures are logged, never raised. Conversational forgetting: `heuristic_extract` detects explicit "forget/erase/scrub <Name>" and "delete entity/note/record <Name>" commands (never "don't forget") into `forgotten_entities`; `process_exchange` first resolves each name through `db.find_entity` (canonical name, then unambiguous `metadata.aliases`), calls `db.drop_entity`, evicts the id from the optional `SessionLedger`, logs `User-directed forgetting: dropped entity '<name>' (id=<n>)` at INFO, discards same-extraction entities/edges/deprecations that reference the forgotten names, and appends `forgotten=N` to the episode log line when non-zero. Enforces the edge requirement and constituent consolidation (Section 6). `strip_markdown_structure` removes heading lines and bold labels so formatting words never become entities. All token/stop-word rules live in `stopwords.py` (`distill.py` keeps no private stop-word list). Edge validity (non-empty fields, no self-loop, valid names, no secrets) is defined once in `_valid_edge` and shared by the edge-requirement check and edge persistence; heuristic and injected extractors (e.g. `LLMExtractor`) go through the same `process_exchange` pipeline. `<think>...</think>` blocks are stripped from the assistant text before sanitization and extraction, so reasoning tokens are never treated as factual assertions (ROB-3). Critique deprecation: `deprecated_edges` from Model B (permanence-marker guardrail, see Personality Matrix) are applied through `db.deprecate_edge` after the turn's entities/edges are upserted; idempotent, never deletes nodes.
- `sanitize.py`: `sanitize_text` replaces matches with `[REDACTED_SECRET]` for: PEM private key blocks, URIs with embedded credentials (DB URIs), JWTs, `Bearer` tokens, GitHub (`ghp_`, `github_pat_`, `ghs_`, `gho_`, `ghu_`), OpenAI-style `sk-`, Stripe `sk_live_`, Slack `xox[bap]-`, Google `AIza`, AWS `AKIA`/`ASIA`, HuggingFace `hf_`, and unclosed PEM blocks (to end-of-string); bounded quantifiers and a 200,000-character input cap prevent ReDoS (Section 4). `is_secret_token` flags candidate entity names that are redaction-affected or are high-entropy: length >= 24, no whitespace, contains letters and digits, Shannon entropy >= 3.5 bits/char.
- `stopwords.py`: Stop-word and filler lists, `is_valid_entity_name` (rejects stop-words/fillers; short names allowed via whitelist), `name_tokens`. Also used by the resolver to skip single-word stop-word concepts. `is_valid_entity_name` accepts any descriptive or hyphenated name for `trait`/`directive`/`preference` (only names without a word character are rejected).
- `session.py`: `SessionLedger`: in-memory, per-session `seen_entity_ids` and `seen_edge_ids` (separate id spaces), idle TTL 3600 s, `filter_new` returns a `SessionDelta`, `reset`, `evict_expired`, `evict_entity(entity_id)` (removes an id from every session so a forgotten entity is treated as gone). Capped at `max_sessions=1000` (`DEFAULT_MAX_SESSIONS`, must be >= 1): `filter_new` re-inserts the active session at the most-recent end and, when a new session would exceed the cap, evicts the least recently used one (ROB-5). `session_id` is limited to 128 characters (`MAX_SESSION_ID_LEN`): `filter_new` raises `ValueError` and the proxy answers HTTP 400. Single event loop only; not persisted. **Multi-turn injection contract (ERG-CTX-005):** clients are assumed to resend only `user`/`assistant` history. `remember_context` stores each injected block per session (<= `MAX_REPLAY_CHARS` = 12000; overflow drops the oldest blocks and un-sees their ids), `replay_context(session_id, present_text, exclude)` returns stored blocks absent from the client system/developer text, and `proxy.py` prepends them (oldest first) before the new delta, so memory is in the prompt on every turn. If the client echoes our prompt nothing is duplicated. `evict_entity` also removes blocks naming the forgotten entity.
- `logging.py`: `strand` logger tree. `RotatingFileHandler` (5 MiB, 2 backups) at `~/.local/share/strand/strand.log` (override `STRAND_LOG_PATH`). Parent directory secured via `perms.secure_parent_dir` (`0700` only for managed `strand` dirs, never `$HOME` or unmanaged parents; SEC-PERM-002), log file always `0600` (re-applied after each rollover). Stderr stream only in debug on a TTY.
- `compactor.py`: `SessionCompactor(db, extractor_url, extractor_model, threshold_hours=24.0)`. `compact_session(session_id)` loads uncompacted episodes (returns immediately when none), sanitizes narratives, asks the local SLM (or a heuristic when `extractor_model` is empty) for `{"entity_summaries": [{"name", "summary"}], "session_summary"}`, updates matching `entities.summary` via `db.update_entity_summary` (provenance-gated; SLM at `model_inferred` 0.6, heuristic at 0.5), then calls `db.mark_episodes_compacted`. `compact_all(older_than_hours=None)` compacts eligible sessions sequentially and returns the count. It never raises. DB methods: `get_uncompacted_sessions(older_than_seconds)` (distinct session ids whose newest uncompacted episode is older than the cutoff), `get_session_episodes(session_id, uncompacted_only=True)`, `mark_episodes_compacted(ids)` (`compacted_at = CURRENT_TIMESTAMP`), `update_entity_summary(name, summary, origin, confidence)`. Config: `compaction_threshold_hours` (default `24.0`, `STRAND_COMPACTION_THRESHOLD_HOURS`). **Phase 2 extraction schema (Chunk 1):** `SYSTEM_PROMPT` asks the SLM for `{"entity_summaries", "session_summary", "discovered_aliases": [{"canonical_name", "alias"}], "operator_profile": {"focus_summary", "inferred_traits": [{"name", "archetype": "preference"|"trait", "relation": "prefers"|"enforces", "summary"}]}}` and instructs it to ignore one-off conversational steering, emitting traits only for sustained patterns across the episodes. `parse_compaction_output(raw_text) -> dict` (uses `common.extract_json`; never raises, never returns None) falls back to empty lists/strings for missing or malformed keys, drops traits whose archetype is outside `PERSONALITY_ARCHETYPES` or whose relation is outside `{prefers, enforces}`, and tags every inferred trait and the `operator_profile` focus summary `origin="model_inferred"`, `confidence=0.60` (model-claimed provenance is ignored). **Persistence (Chunk 2):** the SLM path now parses with `parse_compaction_output` (unparseable JSON still skips the session). After entity summaries, `compact_session` applies: (a) `discovered_aliases` via `db.find_entity(canonical_name)` then `db.merge_entity_alias(id, alias, summary="", origin="model_inferred", confidence=0.60)`; unknown or private canonical entities are skipped silently; (b) `inferred_traits`: the operator is the `user_explicit` person with an `operates_host` edge (fallback: the `User` entity; with neither, steps (b) and (c) are no-ops); each trait is upserted (`model_inferred` 0.60) and linked `(Operator) -[prefers|enforces]-> (Trait)` with weight 1.0 at `model_inferred` 0.60, and the usual provenance precedence in `upsert_entity`/`upsert_edge` means an existing `user_explicit` entity or edge is never displaced, while deprecated edges are never revived; (c) a non-empty `focus_summary` updates the operator summary via `db.update_entity_summary` (`model_inferred` 0.60), which cannot overwrite a `user_explicit` 1.0 summary. All steps run before `mark_episodes_compacted`; any failure is caught by the fail-open wrapper. No schema change. **Privacy (ROB-4):** `_entities` excludes private entities (`archetype == 'private'` or `metadata.private is True`) before the prompt is built, so private names and summaries are never sent to the SLM.
- **Episodic stitching (COG-3):** `DatabaseManager.get_recent_episodes_for_entities(entity_ids, max_age_days=7.0, limit=2, exclude_session_id=None)` returns `[{"id", "narrative", "created_at", "entities"}]` for episodes whose `extracted_entities` JSON array (`json_each`) contains any given entity id and whose `timestamp` is within `max_age_days`, newest first, capped at `limit`; `created_at` is the episode timestamp as UTC `YYYY-MM-DD HH:MM:SS`, `entities` the decoded id list, and episodes of `exclude_session_id` are skipped (the live transcript already holds them). `ContextResolver.resolve` calls it with the directly matched entity ids (after the graph walk), drops ids in the session's `seen_episode_ids`, records the novel ones via `SessionLedger.mark_episodes_seen` and renders, directly under `## Strand Memory` (after any `[Reality Check]` and personality sections, before `[Working Memory]`):
  ```
  [Recent Continuity]
  - YYYY-MM-DD: <narrative, whitespace-collapsed, max 240 chars>
  ```
  The section is omitted when nothing matches, episodes are older than the horizon, or all were already injected this session; episodes touching private entities are suppressed unless private access is allowed, and a DB error fails open to no continuity. Relevance is purely dynamic (matched entities, recency, per-session novelty); no topic or archetype is special-cased. Config: `continuity_horizon_days` (float, default `7.0`, `STRAND_CONTINUITY_HORIZON_DAYS`) and `continuity_max_episodes` (int, default `2`, `STRAND_CONTINUITY_MAX_EPISODES`), passed by `daemon.build_app` to `ContextResolver`.
- `cli.py`: `strand` operator tool (`[project.scripts]`), global `--db`. Commands: `stats`, `list [--archetype --limit]`, `inspect <name|id>`, `drop <name|id> [-y]`, `prune-stale [--confidence-below X]` (default 0.5, removes model_inferred facts), `prune-decayed [--days DAYS] [--dry-run]` (default 90; one atomic transaction via `db.prune_decayed_edges` deleting deprecated edges and cold edges idle > DAYS with `access_count <= 2`, then sweeping `model_inferred` entities left edgeless; `--dry-run` only reports), `compact [--hours FLOAT] [--session TEXT]` (compacts inactive sessions, or one named session regardless of age; prints `Compacted session 'X' (N episodes, M summaries updated)`), `config show|get|set` (`show` masks secrets), `logs [-n N]`. `strand list --archetype trait|directive|preference` filters the personality nodes like any other archetype.

## 4. Security & Privacy Architecture
- **Host telemetry gate (SEC-PRIV-002):** ambient hardware specs (OS release, desktop/session, CPU model, RAM; kernel/OS strings) never leave the machine by default. `Config.enable_host_telemetry` (default `False`, fail-closed; env `STRAND_ENABLE_HOST_TELEMETRY` accepting `1`/`true`/`yes`/`on` case-insensitively, `config.json` key, `strand config get/set`, and the GUI bridge `SETTINGS_KEYS`/`getConfig`) or an in-memory session override (`SessionLedger.set_allow_host_telemetry`, Section 3 `proxy.py`) opens the gate. With the gate closed only `user` and `hostname` are sent, so `(Operator) --[operates_host]--> (Hostname)` anchoring keeps working. No schema change; the override itself is in-memory only. **Conversational opt-in:** during Day Zero onboarding (Turn 4/5) the operator is asked whether to inspect hardware; Model B distills `(<Operator>) --[prefers]--> (Host Telemetry Enabled | Host Telemetry On-Demand)` and the proxy then sets the session override and persists `enable_host_telemetry` (`True` on opt-in, `False` on decline) via `save_config_value` (atomic write, `0600`). Until the operator opts in, no CPU/RAM/OS strings are injected on any turn.
- **FastEmbed model cache (SEC-CACHE-003):** `EmbeddingManager` always passes an explicit `cache_dir` to `TextEmbedding`, never the shared `/tmp/fastembed_cache`. Location: `$FASTEMBED_CACHE_PATH` (operator override), else `$XDG_CACHE_HOME/strand/fastembed`, else `~/.cache/strand/fastembed`. The directory is created `0700` (and re-chmodded `0700` if it pre-exists) before the model loads; the `strand` parent is secured via `perms.secure_parent_dir`. Runtime sandboxing: `packaging/systemd/strand.service` (`ProtectSystem=strict`, `ProtectHome=read-only`, `PrivateTmp=true`) lists `%h/.cache/strand` in `ReadWritePaths`, so weights are writable and persist across restarts. No database schema is involved.
- **POSIX storage isolation:** data and log directories `0700`; DB, WAL, SHM, log files and `config.json` `0600`. Applied at runtime by `db.py`, `logging.py`, `config.py`, not left to umask.
- **Managed vs. unmanaged directories (SEC-PERM-001):** `perms.secure_parent_dir` forces `0700` only on dedicated Strand directories (name `strand`, e.g. `~/.config/strand`, `~/.local/share/strand`, `$XDG_RUNTIME_DIR/strand`; never `$HOME`). Missing directories are created with `mode=0o700`. For any other parent (`$HOME`, `/tmp`, arbitrary roots) the directory mode is never mutated; a warning is logged if it is group/world accessible, and only the leaf files (`memory.db`, `-wal`, `-shm`, `config.json`) and the socket are enforced at `0600`. Used by `db.py`, `daemon.py`, `config.py`, `logging.py` (`setup_logging`, SEC-PERM-002) and `ui/bridge.py`.
- **Inbound auth:** if `STRAND_API_KEY` (or `api_key` in config.json) is non-empty, every `/v1` and `/v1/*` request must send `Authorization: Bearer <key>`. It is compared with `hmac.compare_digest` and failure returns 401 `authentication_error`. `/health` is always open. If the key is empty, auth is disabled. The inbound key is distinct from `STRAND_UPSTREAM_API_KEY`. The upstream key, when set, is the only credential sent upstream. The client's `Authorization` header is forwarded only when neither key is configured.
- **Ingestion defense:** query and response pass through `sanitize_text` before substantive-turn gating, extraction and `record_episode`, so redacted text is what is stored. Entity names and edge endpoints that satisfy `is_secret_token` are dropped. The entropy heuristic applies to candidate names/endpoints only; free text is covered by the regex patterns.
- **Egress guardrails:** an entity is private according to one predicate, `common.is_private(archetype, metadata)`: the archetype is `private` (case-insensitive, trimmed), or `metadata['private']` is `true`, `1`/`1.0`, or the string `"true"`/`"1"` (any case; `"false"` and `0` are not private). It **fails closed**: corrupt JSON, non-object JSON or undecodable metadata counts as private; only absent/blank metadata means "no flags". `resolver`, `compactor` and `distill` all use it, and `db.PRIVATE_ENTITY_SQL` is its SQL twin inside the subgraph CTE (a parity test keeps them identical). `DistillationEngine` never rewrites an existing private entity. Private entities, and edges touching them, are excluded from the delta and from graph traversal unless the request sends `X-Strand-Allow-Private: true` (case-insensitive). The default is no private data to the LLM. The same filter is applied inside the recursive CTE of `get_entity_subgraph` before `LIMIT`, and `SessionCompactor` never sends private entities to the SLM.
- **Prompt-injection guards:** assistant output is untrusted. Entities and edges derived from a model response are clamped to `origin = model_inferred` and confidence <= `0.60` (`MODEL_CONFIDENCE`); `parse_extraction` whitelists fields so model-emitted `origin`/`confidence` are dropped. Assistant responses can never issue `forgotten_entities` or `deprecated_edges` (these come only from the user's query), and a forget executes only when the user's own prompt contains a forget command that names the target (user corroboration).
- **Secret patterns & ReDoS protection:** `sanitize_text` redacts PEM private-key blocks (including unclosed ones, to end-of-string), credentialed URIs, JWTs, `Bearer` tokens, GitHub (`ghp_`, `github_pat_`, `ghs_`, `gho_`, `ghu_`), OpenAI-style `sk-`, Stripe `sk_live_`, Slack `xox[bap]-`, Google `AIza`, AWS `AKIA` and STS `ASIA`, and HuggingFace `hf_` tokens. Regexes use bounded quantifiers (no polynomial backtracking in the URL-credentials pattern) and input is truncated to 200,000 characters before matching.
- **HTTP ingress hardening:** `POST /v1/chat/completions` requires `Content-Type: application/json` (HTTP 415 otherwise; invalid JSON or non-list `messages` is 400; `session_id` > 128 chars is 400). FastAPI `/docs`, `/redoc` and `/openapi.json` are disabled. The body is capped at 10 MiB (`proxy.MAX_REQUEST_BYTES`): HTTP 413 when `Content-Length` exceeds it or when a chunked body crosses it while being read; pathologically nested JSON (`RecursionError`) is 400, never 500.
- **No private-context laundering:** an exchange sent with `X-Strand-Allow-Private: true` is never distilled (non-streaming and streaming), so private facts quoted in the reply cannot be copied into public, un-flagged entities. The skip is logged.
- **Log hygiene:** the "Incoming query" log line contains the query length and an 80-character preview of the *sanitized* query (sanitize first, then truncate).
- **Socket & filesystem isolation:** the UDS is pre-bound under `umask 0o177`, only dead sockets are ever unlinked, and config/data directories are forced to `0700` (Section 3, `daemon.py`/`config.py`).
- **Workspace file deny-list & tool egress redaction (SEC-PRIV-007):** `workspace.is_denied_file` (case-insensitive, on file name or relative suffix) makes `read_file` refuse `.env*`, `*.pem`, `*.key`, `*.pkcs12`, `*.pfx`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`, `id_dsa*`, `*token*`, `*credential*`, `*secret*` and `.git/config` even inside approved roots, returning `{"error": "Access denied: sensitive file policy"}`. `proxy._run_tool_call` runs `sanitize_text` over the JSON tool result before building the `role: "tool"` message when `Config.redact_secrets` is true (default; `config.json` key `redact_secrets`). No schema change.
- **Bounded file reads (ERG-IO-006):** `read_file` reads via `fh.readline(MAX_READ_BYTES + 1)`, so memory per call is capped at ~8 KiB regardless of line length; over-long lines before `offset` are skipped in bounded chunks, and an over-long returned line yields `byte_truncated: true`.
- **Telemetry provenance guard (SEC-PRIV-008):** `onboarding.telemetry_preference` opens hardware telemetry only for a `prefers -> Host Telemetry Enabled` edge that is `origin = user_explicit` with `confidence >= 1.0` whose source is an authenticated operator anchor (a `person` entity that is itself `user_explicit` at confidence >= 1.0). A `model_inferred` edge (hallucination or third-party prompt injection) is ignored, so it can never toggle telemetry or persist `enable_host_telemetry=true`. The closed stance (`Host Telemetry On-Demand`) is honoured at any provenance. No schema change.

## 5. Transport
- **Desktop mode (UDS):** zero-network local IPC at `$XDG_RUNTIME_DIR/strand/strand.sock` (mode `0600`, parent dir `0700`), or any path given by `STRAND_SOCKET_PATH`.
- **Server/container mode (TCP):** `STRAND_HOST:STRAND_PORT`, chosen whenever host or port is set explicitly or `XDG_RUNTIME_DIR` is absent. There is no container image; Strand ships as a systemd user service.
- **TCP details:** Served by uvicorn on `STRAND_HOST:STRAND_PORT` (default `127.0.0.1:8088`). Use this for remote deployments, with `STRAND_API_KEY` set when binding beyond loopback. **Fail-closed guard (SEC-NET-006):** `daemon.enforce_bind_policy` runs before `build_app`; when the transport is TCP, the host is not loopback (`127.*`, `::1`, `localhost`) and no `api_key` is configured, it raises `RuntimeError("Refusing to bind unauthenticated TCP on non-loopback interface ...")`, which `_run` logs as a `SECURITY` error and turns into a clean `SystemExit`. Explicit insecure override: `--insecure-allow-unauthenticated` or `STRAND_INSECURE_ALLOW_UNAUTHENTICATED=1|true|yes` (for isolated networks/tests); with it `daemon.warn_if_exposed` still logs the loud `SECURITY` warning and the server boots. UDS mode and loopback TCP boot normally with no key.
- **UDS details:** socket lifecycle is in the `daemon.py` entry (Section 3). systemd uses `RuntimeDirectory=strand` and `%t/strand` in `ReadWritePaths`.

## 6. Operational Invariants
- **Edge requirement:** a `model_inferred` entity persists only if it is an endpoint of at least one valid edge in the same extraction (valid = non-empty source/target/relation, not a self-loop, valid names, no secrets). Otherwise it is dropped. `user_explicit` entities are exempt.
- **Compaction:** only sessions whose newest uncompacted episode is older than the threshold are compacted (`--session` bypasses the age check). Episodes are never deleted, only stamped `compacted_at`, and are stamped only after the summary step succeeds, so a session is compacted at most once and retried if the SLM fails. Compaction summaries obey provenance: they never displace a higher-confidence summary, nor a `user_explicit` one at equal confidence, and keep the stored origin/confidence. SLM output is sanitized and capped at 300 chars per summary; unknown entity names are ignored.
- **Provenance:** extractions without attribution are `model_inferred` at confidence 0.6. On upsert, higher confidence wins and `user_explicit` is never displaced at equal confidence.
- **Upstream failure rollback:** since facts are marked seen when resolved, any upstream failure (connect/send error, status >= 400, body-read error, stream interrupted mid-relay) calls `ledger.reset(session_id)` so the next request replays the full context. Failed or interrupted exchanges are never distilled. Client disconnects and cancellations mid-stream, in-stream SSE `error` events, and streams that end without `[DONE]` or a `finish_reason` follow the same rule: `ledger.reset(session_id)`, no distillation; the upstream connection is always closed (`BackgroundTask(upstream.aclose)` plus a shielded `aclose` in `relay`), and a mid-stream `HTTPError` is surfaced to the client as an SSE error event.
- **Forgetting corroboration:** a conversational forget is executed only when the user's own prompt in that turn contains a forget command that names the target entity; `forgotten_entities` proposed by an assistant response or an extractor SLM that the prompt does not corroborate are ignored and logged.
- **Stream disconnect & mid-stream error rollback:** an exchange is distilled only if its stream completed normally (`[DONE]` or non-null `finish_reason`) with no in-stream `error` payload and no client disconnect; every other outcome resets the session ledger so the next request replays the full context.
- **Reasoning-block stripping:** `<think>`, `<thinking>`, `<thought>` and `<reasoning>` blocks (case-insensitive, multiline, closed only by their own tag; an unclosed block runs to the end). `_stream_text` also reads list-form `delta.content` (`[{"type": "text", "text": ...}]`, joined with no separator) instead of dropping the chunk. Stripped text never reaches distillation or extraction; it is removed in `_stream_text`, `DistillationEngine.process_exchange` and `LLMExtractor`. Only `choices[0]` (`index == 0`) contributes to streamed assistant text.
- **Private exclusion before `LIMIT`:** private entities are excluded inside the recursive CTE of `get_entity_subgraph`, before the SQL `LIMIT`, so they never consume hop/edge slots; the resolver's post-filter and the compactor's prompt filter are additional layers, not substitutes.
- **Bounded resources:** at most 4 background distillations run concurrently, the session ledger holds at most 1000 sessions (LRU eviction) and session ids are at most 128 characters.
- **Alias matching:** exact = casefolded whole-word match of the entity name or any `metadata.aliases` entry (word boundary enforced only on word-character edges, so `C++` matches). Constituent = whole-word match of a single token of a name/alias (>= 3 chars, not a stop/function word). Ranking: confidence desc, exact before constituent, first mention, id.
- **Constituent consolidation (write side):** a single-word candidate with no entity of its own that equals an alias or token of exactly one multi-word entity (`Acme` -> `Acme X540`) refreshes that entity's `updated_at` instead of creating a node. Ambiguous matches are not consolidated.
- **Dedup / alias merge gate (write side):** before `DistillationEngine` inserts a candidate entity it calls `db.find_duplicate_entity`. A candidate equal (casefolded) to an existing entity name or `metadata.aliases` entry resolves to that entity; otherwise, when vectors are enabled, the nearest entity within `dedup_distance_threshold` (L2 <= 0.45) with the **same archetype** is the canonical entity (a `system` never merges into a `concept`). A merge inserts no row: the candidate name is appended to `metadata.aliases` (no duplicates), an empty summary is filled from the candidate, confidence/origin follow the provenance precedence above, and `updated_at` is bumped so `ContextResolver`'s alias scanner recognizes the alias on the next recall. Every edge in the same extraction that named the candidate is wired to the canonical entity id. Without sqlite-vec or an embedder only the exact/alias string check applies. An exact-name hit is a normal upsert, not a merge.
- **Edge deprecation (contradiction resolution):** `DistillationEngine` processes `deprecated_edges` after entities and active edges, mapping endpoints to canonical ids (names merged/consolidated this turn, else db alias resolution) and calling `db.deprecate_edge`; each deprecation logs at INFO. Episodes are never altered. `ContextResolver.gather` requests `active_only` subgraphs and also drops any edge with `weight <= 0.0`, `confidence < 0.2` or `metadata.deprecated is True`, so deprecated edges are never traversed or injected. The heuristic fallback detects basic negation (`I sold X`, `I no longer use X`, `I stopped using X`) as a `User -> X` deprecation; otherwise `deprecated_edges` is empty.
- **Temporal access decay & reinforcement:** `ContextResolver.resolve` calls `db.touch_access` for every entity and edge id gathered into the context (including facts already seen this session, so active knowledge stays reinforced); a touch failure is logged and never blocks recall. With `decay_enabled = false` (the "Permanent" horizon) ranking is the legacy `confidence * weight` (entities: confidence first, then match tier/position) and nothing is pruned. With it enabled (the default, Balanced 30d with `decay_half_life_days = 30.0`), `resolver.effective_priority` = `confidence * weight * decay_factor * frequency_factor`, where `delta_days = (now - (last_accessed_at or created_at)).total_seconds() / 86400.0` (edges fall back to `updated_at`), `decay_factor = 2.0 ** (-max(0.0, delta_days) / decay_half_life_days)` and `frequency_factor = min(1.5, 1.0 + 0.05 * access_count)` (entities have weight 1.0). Matched entities are sorted by effective priority (then match tier, first mention, id), subgraph edges by hop, then effective priority, and any entity or edge below `0.15` is pruned. Facts without a usable timestamp are treated as fresh.
- **Conversational forgetting:** user-directed forgetting is a permanent hard delete like `strand drop`: `db.drop_entity(id)` removes the entity, every edge touching it and its `entity_embeddings` row (when vectors are active) in one WAL transaction. Names resolve by casefolded canonical name or an alias that identifies exactly one entity; an ambiguous or unknown name is a logged no-op that never raises, and the episode is still recorded. A forgotten entity (and its aliases) is never re-created or linked by the same extraction, and is evicted from active `SessionLedger` sessions (`DistillationEngine(ledger=...)`, wired by `daemon.build_app` and `proxy.create_app`). Only the user's explicit command triggers it; model-inferred forgetting is not supported. **Episode scrubbing (SEC-MEM-009):** in the same transaction `drop_entity` removes the id from every `episodes.extracted_entities` list, deletes episodes that referenced only that entity, and replaces the entity name and aliases (case-insensitive) with `[forgotten]` in the remaining narratives, so compaction cannot resurrect it. No schema change; `drop_entity(id, scrub_episodes=False)` skips this for the generic-User merge in `onboarding.reanchor_generic_user`.
- **Turn gating:** trivial exchanges (short greeting/acknowledgment queries without a fact assertion, empty or boilerplate replies) are not distilled.

## 7. Graceful Degradation & Diagnostics
- **Embedder fallback:** `embed.create_embedder()` returns a lazy `EmbeddingManager`, or `None` when `fastembed` is not installed (logs `[WARNING] [embed] fastembed unavailable; falling back to lexical-only matching.`). `daemon.build_app` passes it straight to `ContextResolver(..., embedder=...)`, so a `None` embedder means lexical-only mode. If the lazy import or model load fails (corrupt install, offline weights), `EmbeddingManager` logs the same warning once and raises `EmbeddingUnavailable` on every later call; the resolver treats that as "no semantic hits", `DatabaseManager` writes without an embedding, and `embed-backfill` exits 1 with a message.
- **sqlite-vec fallback:** if the extension fails to load, `DatabaseManager.connect` logs `[WARNING] [db] sqlite-vec extension failed to load; vector indexing disabled.`, skips creating `entity_embeddings`, and sets `vec_enabled = False`. Entities, edges and episodes work normally; embedding writes, auto-embedding, `find_similar_entities` (returns `[]`) and the resolver's semantic tier are skipped; `strand drop` skips the vector delete; `embed-backfill` exits 1.
- **Compaction fallback:** if the extractor SLM is unreachable, errors, or returns unparseable JSON, `SessionCompactor` logs `[WARNING] [compactor]` and skips the session, leaving its episodes uncompacted; `strand compact` prints a `Skipped session` line and still exits 0.
- **`strand doctor`** (`cli.py`): prints a checklist (`[ok]`, `[warn]`, `[fail]`) for DB path and journal mode, sqlite-vec status, fastembed install and model cache (the isolated `embed.fastembed_cache_dir()`; the path is reported whether or not the model is cached), extractor SLM reachability (`GET {extractor_url}/models`, timeout 0.5 s; a failure is `[fail]` only if `extractor_model` is configured), and the active transport (UDS path or TCP host:port). It always exits 0.

## 8. Security Hardening (Phase 2)
- **Ingestion immunity (SEC-1):** assistant output is untrusted. `heuristic_extract` forces every entity/edge parsed from a response JSON block to `model_inferred` at confidence <= `MODEL_CONFIDENCE`, and ignores any `forgotten_entities`/`deprecated_edges` in it (they come only from the user's query). `parse_extraction` copies whitelisted fields only, so model-emitted `origin`/`confidence` are dropped. `DistillationEngine.process_exchange` executes a forget only when the user's prompt contains a forget command and mentions the target name.
- **Streaming (SEC-2):** streaming requests are sent upstream with `Accept-Encoding: identity`; chunks are relayed with `aiter_bytes()`; SSE text is split on `\n` only (never `splitlines()`).
- **Fail-open memory (SEC-3):** any exception from `resolver.resolve` is logged with `exc_info`, the session ledger is reset, and the request is forwarded without injected context.
- **Ingress (SEC-4):** `POST /v1/chat/completions` requires `Content-Type: application/json` (parameters like charset allowed), else HTTP 415. FastAPI `/docs`, `/redoc` and `/openapi.json` are disabled.
- **Sanitizer (SEC-5):** input is capped at 200,000 characters before regex processing; the URL-credentials pattern uses a lookbehind and bounded quantifiers (no polynomial backtracking). Extra patterns: Stripe `sk_live_`, Slack `xox[bap]-`, AWS `ASIA`, GitHub `ghs_`/`gho_`/`ghu_`, HuggingFace `hf_`, and unclosed PEM private-key blocks (redacted to end-of-string).
- **Config (SEC-6):** `load_config(strict=True)` (used by `daemon.main`) raises `ValueError` on unreadable/corrupt `config.json`, and the daemon exits with a configuration error; the CLI stays lenient. `Config.from_env` picks `env` (non-empty) then the file value whenever it is not `None`, so explicit `0`, `0.0` and `""` survive.
- **Secret masking (SEC-CONF-008):** `cli.mask_secret` (used by `strand config show` and `strand config set` for `api_key` and `upstream_api_key`) returns `""` for empty/`None`, a fixed `********` for any secret shorter than 16 characters (no prefix/suffix revealed), and `first3...last4` (e.g. `sk-...abcd`) for secrets of 16+ characters.
- **Log levels & privacy (SEC-LOG-004):** `distill.py` (and the `db.deprecate_edge` idempotency trace) log anything containing graph content (entity names, relation triples, forgetting targets, deprecation reasons) at `DEBUG` only, for opt-in troubleshooting. At the default `INFO` level the journal (`journalctl --user -u strand`) carries only operational lines: session ids, gate decisions and counts such as `Recorded episode id=1 session='s' entities=2 edges=1 deprecated=0 forgotten=1`. Keep new distillation logging on this split.
- **Payload clamps (SEC-MEM-008):** `DistillationEngine._upsert` clamps every entity summary to `MAX_SUMMARY_LEN` (300) on all paths (heuristic and JSON block); `db.record_episode` clamps narratives to `MAX_NARRATIVE_LEN` (600). Raw blobs cannot enter `entities.summary` or `episodes.narrative`.
- **Compactor privacy (SEC-MEM-010):** `SessionCompactor` never updates the summary of a private entity (`is_private`), and `db.update_entity_summary` fails closed (returns False) for private entities regardless of caller.
- **Safe metadata inspection (BUG-CLI-007):** `strand inspect` reads `entities.metadata` through `common.load_metadata` and never calls raw `json.loads` on it for display. Corrupt, undecodable or non-object metadata (e.g. `{not-json`, `[1, 2]`) shows `metadata:   {corrupted}` with no aliases, while ID, name, archetype, origin, confidence, summary and one-hop edges render normally and the exit code stays 0. Valid metadata prints as sorted JSON. Read-only; no schema change.
- **URL credential masking (SEC-CLI-005):** `cli.mask_url` (used by `strand config show` for `upstream_url`/`extractor_url` and by `strand doctor`) parses with `urllib.parse.urlsplit` and replaces an embedded password with `********` (`https://user:********@host/v1`); a bare token without a colon becomes `********@host`; URLs without credentials, and empty/`None` input, pass through (empty string for `None`). A parse failure falls back safely without raising. `strand config get <key>` deliberately prints the raw value.
- **Exception URL masking (SEC-NET-008):** `common.safe_exc` (with `common.mask_url`, relocated from `cli`) formats upstream failures as `Type: message` with every URL's `user:pw@` masked. `proxy.py` (logs, 502 bodies, SSE error frames), `extractors.py` and `compactor.py` never log or return raw `httpx` exception text.
- **Query log levels (SEC-LOG-005):** `proxy.py` logs `Incoming query length=%d session=%r` at `INFO`; the sanitized 80-character preview is `DEBUG` only, so user prompt text stays out of journals at default verbosity.
- **`strand mark-private <name|id|alias>` (SEC-PRIV-009):** `cli.cmd_mark_private(db, target)` resolves the entity (id, case-insensitive name, then unambiguous alias via `db.find_entity`), sets `metadata["private"] = true` (other metadata preserved) through `db.update_entity_metadata(id, metadata)` and prints `Marked entity '<name>' (id=<id>) as private.`; an unknown target prints an error to stderr and exits 1. Private entities are then excluded from resolution unless `allow_private`. No schema change.

- **Workspace & host awareness, Ring 1 (Phase 8A):** `tools/workspace.py` adds four tools to `WORKSPACE_TOOLS` and `dispatch_tool_call`, all confined to `workspace_roots` by `is_safe_path` (outside paths fail closed with `access_denied`).
  - `grep_workspace(pattern, path=".", max_results=20)`: Ring 0 regex search that uses `rg --json` when `shutil.which("rg")` finds it and otherwise a pure-Python scan (skips hidden and vendored dirs, symlinks, binaries and files over 2 MB). It returns `{path, line_number, line_text}` capped at 20 matches / 4 KB (lines clipped to 200 chars) and skips files matching the read deny-list.
  - `write_file(path, content)` and `patch_file(path, search_block, replace_block)`: dual-track safety. *Git track:* a file inside a git repository must be clean in `git status` (otherwise `git_dirty`); no snapshot is written because git is the undo. *Loose track* (Obsidian vaults, approved docs): an atomic snapshot goes to `~/.local/share/strand/backups/<timestamp>_<filename>` (dir `0700`, files `0600`, plus a `.meta` sidecar recording the original path) before any change; if the snapshot fails the file is untouched. `patch_file` needs an exact, unique `search_block`; zero or multiple matches return `search_not_found` / `search_ambiguous` without touching disk. Writes are atomic (temp file + `os.replace`), capped at 256 KB.
  - `restore_backup(backup_id)`: reverts a file to its snapshot (a snapshot of a newly created file deletes it). The backup must live in the backup directory, the recorded target is re-validated against the roots and write deny-list, and the pre-restore state is journaled so a restore is itself undoable (`redo_backup`).
  - **Write guardrail:** targets inside `~/.config/strand/` or `~/.local/share/strand/` (including the journal), `.git/` internals, and `.env*`, `*.key`, `id_rsa*` (plus the read deny-list: keys, certs, tokens, credentials, secrets) are denied with `access_denied`.
  - **Ephemerality:** tool arguments and results (file bodies, search and replace blocks) travel only through the `role: tool` messages of the active turn; the ledger evicts them from earlier turns and nothing from them is written to `memory.db`. Tool output is still passed through `sanitize_text` when `redact_secrets` is on.

### UI shortcuts
| Key | Action |
| --- | --- |
| `Enter` / `Shift+Enter` | Send / newline |
| `Ctrl+L` | New conversation: `Bridge.newConversation()` aborts any running turn, clears history, rotates `session_id` (`ui-<hex>`) and emits `conversationReset`, which clears the transcript |
| `Esc` | Busy: `Bridge.abort()` cancels the stream (partial text is kept and marked `[stopped]`, and it enters history). Idle: clears the input |
| `Up` / `Down` | In an empty input (or while already browsing), step through up to 100 recently sent prompts and slash commands (`historyPrevious`/`historyNext`); `Down` past the newest restores an empty input |
| `Ctrl+D` | Toggle the diagnostics drawer (also the small header icon) |

Abort works by cancelling the asyncio task on the worker thread (`loop.call_soon_threadsafe(task.cancel)`); closing the HTTP stream lets the daemon see the disconnect and reset the session ledger as for any client disconnect. Each turn carries a generation counter, so a turn aborted by a reset never writes into the new session's history.

### Local slash commands
Handled by `Bridge.runCommand` (parsed by `parse_command`: one leading `/word` only, so `/etc/hosts ...` is a normal prompt). They are never sent to the daemon or upstream and are not added to chat history. Feedback is shown as a dim note in the transcript.
- `/new`: same as `Ctrl+L`.
- `/private on|off`: adds the header `X-Strand-Allow-Private: true` to subsequent requests (off by default, per Section 4); the header lock glyph shows amber while on. Without an argument it reports the state.
- `/model <name>`: switches the model for subsequent requests; the input-dock watermark and drawer follow (`modelChanged`). Without an argument it reports the current model.
- `/onboard`: resets the session like `/new`, flags it onboarding (`X-Strand-Mode: onboarding` on its requests until the next `/new`/`Ctrl+L`) and immediately sends a synthetic trigger turn so Strand opens the conversation; the trigger stays in history only for the upstream call.
- `/help` lists them; an unknown `/word` reports an error locally.

### Onboarding mode (COG-2, context resolution)
After `resolver.resolve`, `proxy.py` decides whether the session is an onboarding session and records its mode in an in-memory, bounded map (so later turns without the header stay in the same mode). **Day Zero** is the DB holding 0 `person` entities with `origin = 'user_explicit'` (`count_operators`); `X-Strand-Mode: onboarding` (sent by `/onboard`) with an explicit operator already present selects **Intent Triage** instead (OBS-POL-004). `onboarding_directive(host_info, mode, first_turn)` is prepended to the system delta: Day Zero turn 1 mandates the opening "Hi, I'm Strand. What should I call you?" and forbids addressing the operator by `$USER`; later turns are natural, unhurried peer dialogue: greet by name, acknowledge the hostname, explain in 1-2 plain sentences what Strand does (local memory so the operator needn't re-explain things to models, sensitive info stripped before anything goes out) and explore the current workbench focus, tech stack and communication stances (terse diffs, zero corporate fluff); triage offers (1) update identity, (2) recalibrate directives/tone/formatting, (3) re-run onboarding, and points full wipes to Settings. Host specs stay ambient. Nothing is seeded from `$USER`; there are no procedural name heuristics. The operator's name is anchored by **Model B semantic distillation**: `LLMExtractor`'s `SYSTEM_PROMPT` instructs the model that when an exchange identifies or confirms the operator's preferred name ("Alice", "Just Alice", "Alice works", "Alicia is fine", "Call me Alice"), it emits a `person` entity (`origin: "user_explicit"`, `confidence: 1.0`) and the edge `(<Declared Name>) --[operates_host]--> (<Hostname>)` (the hostname is passed in a `Host:` line of the extractor input). `parse_extraction` honours model-emitted `user_explicit`/1.0 only for a `person` entity (and that entity's `operates_host` edge); everything else stays clamped to `model_inferred`. After each distillation `proxy.py` calls `onboarding.reanchor_generic_user`, which folds any stored generic `User` node and its edges into the explicit operator (no-op when none exists). `parse_name_answer`, `declared_name`, `anchor_declared_operator`, the `?` rejection, the 6-word ceiling, the `EXPECTING_NAME` flag, `expecting_name` session tracking and `onboarding.anchor_operator_name` were removed. Day Zero ends when Model B declares an operator (`count_operators() > 0`); digressions or non-names simply leave it open and Model A keeps the conversation going. **Permanent graduation (two-factor):** `onboarding.is_onboarding_completed(db)` is True only when (a) `count_operators(db) > 0` and (b) `telemetry_preference(db) is not None` (the operator resolved the hardware choice as Enabled or On-Demand). When True and the request lacks `X-Strand-Mode: onboarding`, `proxy.py` skips Day Zero entirely: no `onboarding_directive`, no onboarding session flag (a session already flagged in this process finishes its resolved-telemetry turn so the specs acknowledgement lands), so new `strand chat` / `strand-gui` sessions on an onboarded database never run intake turns; `/onboard` still selects Intent Triage. **Task-Yield rule:** every directive carries the `TASK-YIELD CONSTRAINT` (execute or report imperative commands, tool instructions, edits and debugging tasks plainly, then STOP with no onboarding questions or filler) and a default question budget of 0 (ask only when blocked by ambiguity or missing parameters); on an affirmative telemetry answer the model briefly acknowledges hostname/RAM/cores and yields. No schema change. Resolution failures fail open with no directive. `SessionLedger` is untouched, and distillation runs as usual on every turn except the synthetic `/onboard` trigger prompt.

### Rendering & window state
- Assistant replies are split by `split_markdown` on ``` fences (`Bridge.segments`): prose renders as Markdown, fenced code in a monospace block with a darker tinted background, border and optional language label. An unclosed fence during streaming renders as code until it closes.
- **Client-side stream pacing (OBS-ERG-003):** the socket read and the proxy relay are never throttled. `Bridge._consume` appends each SSE text chunk to an in-memory `deque` (`Bridge._relay`, tagged with the conversation generation) and a GUI-thread `QTimer` (16 ms) drains it into `chunkReceived` at ~65-70 tokens/s (default 67, ~270 chars/s; retuned from ~40; ~1.07 token credit, i.e. ~4-5 chars, per 16 ms tick) (`PACE_TOKENS_PER_SEC`, ~4 chars/token credit; no burst after idle gaps; the first chunk shows immediately). `streamFinished` and `busy=false` are deferred until the buffer is empty; errors and aborts flush what was received first. `Bridge.flush_stream()` (slot) instantly drains the whole buffer; in `main.qml` a `Tab` `Shortcut` (enabled only while `bridge.busy`) calls it, fast-forwarding like CLI tab-completion. `newConversation` discards buffered chunks; `Bridge(pace_tps=0)` disables pacing. History and diagnostics still use the full unpaced text.
- **Hybrid bubble/canvas layout (OBS-UI-002):** `split_blocks` (via `Bridge.blocks`) classifies a reply into `prose`, `code` (``` fences), `table` (>= 2 consecutive pipe lines) and `data` (>= 3 consecutive `key: value` lines, or a `{`/`[` block). Prose renders in assistant bubbles (`proseBubble`: surface `#161b22`, 1px `#30363d` hairline, radius 12, `assistantFamily` = Inter -> IBM Plex Sans -> Source Sans 3 -> Noto Sans -> Segoe UI -> sans-serif) that hug their text width (a hidden no-wrap `Text` measures the natural width, capped at the flow width `min(85%, 820)`, one-way geometry). Code, tables and data break out of the bubble onto the recessed canvas as `codeBlock` cards. The thinking pill, user cards and notes keep the single `bubble`.
- **Multi-bubble paragraphs & identity headers (OBS-UI-002):** `split_blocks` splits prose on blank lines (`PARAGRAPH_SPLIT_RE`), so each paragraph is its own `prose` block and `main.qml` stacks them as separate `proseBubble`s with a 6px gap; code/table/data blocks remain single cards. In the transcript, the first row of a speaker group renders an identity header (24px) above its bubble: user rows are right-aligned with the operator name (`Bridge.operatorName`: `$STRAND_UI_OPERATOR` -> login name -> `Operator`) in muted 11px uppercase plus an avatar circle; assistant rows are left-aligned with `STRAND` in `#38bdf8` (0.85 opacity) and the brand pip. Gaps between rows: 30px on a speaker change, 6px within a turn, 12px around notes (the `ListView` spacing is 0; each delegate owns its top gap). Palette: canvas `#0a0c10`, user `#182234`/`rgba(255,255,255,0.08)`, assistant `#13171f`/`rgba(56,189,248,0.14)`, cards `#0d1117`/`rgba(255,255,255,0.06)`.
- **3-beat conduit glyph (OBS-ERG-003):** `ConduitGlyph.qml` replaces the static brand dot (24x24 header), is the thinking placeholder in the pending assistant bubble and is mirrored (18x18) in the telemetry corner button while active. It sets `layer.enabled: true` and `layer.smooth: true`; idle (`!bridge.busy && !bridge.distilling`) is static with its single `NumberAnimation` at `running: false` (0% CPU). Beat 1: `bridge.grounding` (150 ms single-shot strike set on submit, cleared by the first chunk) lights the core node cyan `#38bdf8`. Beat 2: `bridge.busy` runs a left-to-right cyan wave. Beat 3: `bridge.distilling` (true for 1.8 s after `streamFinished`, via a single-shot `QTimer`) runs an amber `#f59e0b` right-to-left pulse.
- **Grounding pulse (OBS-ERG-003):** `proxy.py` reports the resolved delta on the response as `X-Strand-Grounding: entities=N edges=M ...` (the `_delta_log_fields` string; also on non-streaming replies). The bridge parses it (`parse_grounding`); if any count is non-zero `groundingPulse` is true and the first paced token is held ~150 ms (`GROUNDING_HOLD_S`) so retrieval is perceptible. The header `brandDot` breathes faster/deeper with a lighter tint while `groundingPulse`, then settles to its resting active state once the first token is shown. `groundingSummary` carries the human-readable counts.
- Window size persists across launches via `QSettings("strand", "strand-gui")` (native per-user location). `width`/`height` (keys `window/width`, `window/height`) are saved by `app.save_size` on every resize (debounced 300 ms) and on `aboutToQuit`, each followed by `settings.sync()` for an immediate disk flush. `app.restore_size` re-applies them clamped to a minimum of 480x500 (invalid values are ignored). This is the Wayland-safe part: compositors (e.g. KDE Plasma 6) forbid client-side absolute positioning, so size is the only geometry guaranteed to persist.
- The `(x, y)` position (`window/geometry`) is restored by `app.restore_geometry` only when the Qt platform is not `wayland`, ignoring values below the minimum size or fully off every attached screen; any exception while positioning is swallowed, so a rejected request never warns or fails. This is UI state only; it does not touch `config.json` or the daemon.
- Stream-abort resilience: `Bridge._stream` treats `asyncio.CancelledError` as a clean `[stopped]` abort, `httpx.HTTPError` as an error, and any other exception as an error (or a silent abort when `Esc` was pressed); `abort()` tolerates an already-closed event loop; the worker thread target catches `CancelledError`, `httpx.HTTPError` and `Exception` and always clears loop state and runs `on_done`, so an abort can never crash the Qt runtime or leave the input busy.
- **UI egress restriction (SEC-NET-007):** the GUI never makes network requests on behalf of transcript text. `bridge.neutralize_images` runs inside `split_markdown` (hence `Bridge.segments` and `Bridge.blocks`) and rewrites Markdown images (`![alt](url)`, `![alt][ref]`) in non-code text to `[image: alt]` (or `[image]`), dropping the URL, so `Text.MarkdownText` cannot fetch remote resources or leak the operator IP/query data. Regular `[label](url)` links, bold, code and lists are unchanged. As a second layer `app.install_egress_guard` gives the QML engine a network access manager that only allows `file`, `qrc` and `data` URLs. The only network path from the UI remains the daemon connection via `httpx`.
- None of this changes the transport: the socket path, the `0700`/`0600` modes and the daemon contract are untouched.

## 10. JIT Workspace Boundary & Substrate Independence
See `CONSTRAINTS.md` for the governing laws. Status: built (Phase 7, `WS-1`..`WS-3`): `src/strand/tools/workspace.py` is the runner, `proxy.py` runs the execution loop and `SessionLedger.compact_history` evicts transient payloads.

- **Ephemeral runtime streams:** file inspections (`read_file`, `list_directory`) and image payloads are transient runtime streams handled by tools during the active turn. They are never written to `memory.db`: no code files, diffs, AST trees, terminal dumps or base64 images in any table. Only distilled relational takeaways (entities, edges, episodes, stances) persist, through the normal sanitized distillation path.
- **Just-in-time pull:** workspace state is read live, on demand, by scoped tools. There is no background crawler, sync or duplicate of local files. Tools are confined to configured `workspace_roots` (Ring 0, windowed reads with hard size caps such as 8 KB per call); mutation (Ring 1) and shell or egress (Ring 2) are gated as defined in `CONSTRAINTS.md`.
- **Proxy tool loop (`WS-2`):** when `config.tools_enabled` is true, `proxy.py` merges `WORKSPACE_TOOLS` into the outgoing request's `tools`. If the upstream reply contains tool calls for those tools, the proxy runs them locally with `dispatch_tool_call` against `config.resolved_workspace_roots()`, appends the assistant message (with `tool_calls`, preserving provider-specific fields such as `thought_signature`, `extra_content` and `reasoning_content` verbatim, including those accumulated from SSE deltas) and one `role: "tool"` message per call (`tool_call_id` plus the JSON result), and re-posts, for at most `MAX_TOOL_ITERATIONS` (5) rounds; a final request with `tool_choice: "none"` forces an answer if the model keeps looping. For SSE, tool-call turns are buffered and never relayed; a turn that starts with plain text streams live. Calls to tools Strand does not own pass through to the client untouched. With `tools_enabled` false nothing is attached and nothing is executed.
- **Multi-root relative path resolution (`ERG-PATH-004`):** `is_safe_path` (used by `read_file` and `list_directory`) expands `~` first. Absolute paths are resolved and must sit inside a root. Relative paths are tried against each root in `workspace_roots` (an existing candidate wins, otherwise the first candidate bounded by its root), then against `os.getcwd()`, accepted only if it resolves inside an approved root. This lets models pass bare relative paths even when the daemon's cwd is `$HOME` under `systemd --user`. Candidates that escape every root (`../` traversal, symlink escape) are denied with `access_denied`.
- **Transient ledger entries (`WS-3`):** `SessionLedger.compact_history` runs on every request: in turns before the latest user message, `role: "tool"` content over `TOOL_EVICT_MIN_CHARS` and inline media parts are replaced by short placeholders, while assistant syntheses stay. Distillation only ever receives the last user query and the final assistant text (never tool messages or buffers), so no tool output reaches `memory.db`.
- **No external indexer substrate:** Strand is a single embedded SQLite graph. External indexer databases (for example a Weaver DB) are **not attached, synced or integrated**; physical truth stays on disk and in Git, cognitive truth stays in `memory.db`.
- **Unchanged transport and privacy:** UDS `0600`/`0700`, fail-closed egress and zero telemetry apply to every tool path.
- **Workspace file deny-list & tool egress redaction (SEC-PRIV-007):** `workspace.is_denied_file` (case-insensitive, on file name or relative suffix) makes `read_file` refuse `.env*`, `*.pem`, `*.key`, `*.pkcs12`, `*.pfx`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`, `id_dsa*`, `*token*`, `*credential*`, `*secret*` and `.git/config` even inside approved roots, returning `{"error": "Access denied: sensitive file policy"}`. `proxy._run_tool_call` runs `sanitize_text` over the JSON tool result before building the `role: "tool"` message when `Config.redact_secrets` is true (default; `config.json` key `redact_secrets`). No schema change.

## 11. Historical Facts, User Provenance & Collection Traversal
- **Deprecation boundary (`extractors.SYSTEM_PROMPT`):** `deprecated_edges` is reserved for facts the user says were WRONG, cancelled or should be forgotten (or relationships that ended). Biographical history ("I used to own an W34") is an ACTIVE `previously_owned`/`owned` edge at normal weight, never a deprecation.
- **Direct-declaration provenance (`parse_extraction`):** an edge `(Operator) -[owns|owned|previously_owned|prefers|demands]-> (X)` (source a declared operator or `User`/`Operator`/`Me`/`I`) is tagged `user_explicit` at `1.0`, as is its target entity. Everything else stays untagged and the engine clamps it to `model_inferred` at 0.60.
- **Collection traversal (`ContextResolver.match_entities`):** a query with an archetype word (`car(s)`, `vehicle(s)`) plus a self/history word (`my`, `history`, `past`, `owned`, ...) leads the match list with active `vehicle` entities linked to the operator (`User` or a `person` with an `operates_host` edge) by `owns`, `owned` or `previously_owned`. Severed edges and private entities are excluded; `gather` then walks them with `active_only=True`.


## Service Readiness & Active Doctor Probe
- **`Type=notify`:** `packaging/systemd/strand.service` uses `Type=notify` with `NotifyAccess=all`, so `systemctl --user start strand` blocks until the daemon reports ready. `daemon.notify_ready()` is a zero-dependency `sd_notify` (sends `READY=1` as a datagram to `$NOTIFY_SOCKET`; a leading `@` becomes an abstract-namespace `\0`; no-op when unset; errors swallowed). In socket mode `_secure_socket` calls it once uvicorn has started (lifespan startup, i.e. SQLite connect and migrations, finished, socket listening and `chmod 0600`). In TCP mode a daemon thread polls the port and then notifies.
- **Active `strand doctor` probe:** after the static checks, `cli._probe_daemon` issues `GET /health` over the configured UDS (`$XDG_RUNTIME_DIR/strand/strand.sock` by default; TCP otherwise) with a 0.5s timeout. 200 prints `[ok]   daemon: active (listening on strand.sock)`; anything else prints `[fail] daemon: unreachable (...)` with `systemctl`/`journalctl` hints and `doctor` exits 1. Static degradations remain warnings.
- **Installer gating:** `scripts/install.sh` polls `systemctl --user is-active --quiet strand` for ~5s after enabling the unit; if not active it prints `[ERROR] Strand daemon failed to start under systemd.`, the last 15 journal lines, and exits 1. `strand doctor` runs only after that. No schema changes.
